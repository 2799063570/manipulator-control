# 核心知识点与面试八股

## ROS 2

**Q：Topic、Service、Action 如何选？**  
A：连续数据流用 Topic，如传感器和速度命令；一次请求/响应且耗时短用 Service，如读取配置；可运行较久、要进度和取消的任务用 Action，如机械臂轨迹和导航目标。`FollowJointTrajectory` 采用 Action 是因为轨迹需要反馈、抢占和取消。

**Q：QoS 为什么重要？**  
A：它定义可靠性、历史深度、持久性。传感器常用 `best_effort` 降低阻塞，控制状态和关键事件通常用 `reliable`。两端 QoS 不兼容会“看得到 topic 但收不到数据”，须用 `ros2 topic info -v` 检查。

**Q：ROS 2 是实时的吗？**  
A：ROS 2 可用于实时系统设计，但默认 Linux、DDS 配置和普通节点不保证确定性。硬实时循环应使用实时内核/线程优先级、避免动态内存与锁，并把电流/速度内环放在驱动器或 MCU。

## TF、URDF、状态估计

**Q：`map`、`odom`、`base_link` 的区别？**  
A：`base_link` 随机器人运动；`odom` 局部连续但长期漂移；`map` 全局一致但定位修正可跳变。通常 SLAM/AMCL 发布 `map->odom`，EKF/里程计发布 `odom->base_link`。

**Q：URDF 的 visual、collision、inertial 分别做什么？**  
A：visual 仅显示，collision 用于碰撞检测/物理接触，inertial 决定动力学。三者应分别建模，尤其 collision 不能直接用高精度视觉网格。

## 机械臂运动学与控制

**Q：正运动学、逆运动学和雅可比？**  
A：FK 由关节角求末端位姿；IK 反过来由目标位姿求关节角，可能无解或多解；雅可比满足 `xdot = J(q) qdot`，连接关节速度与末端速度。

**Q：为什么奇异位形危险，DLS 如何处理？**  
A：奇异时 J 秩下降，伪逆会放大噪声，产生很大的关节速度。DLS 使用 `Jᵀ(JJᵀ+λ²I)⁻¹`，以少量精度换取有界速度；λ 可随最小奇异值增大。它不能替代避奇异的路径规划和速度限制。

**Q：三次与五次插值的区别？**  
A：三次通常保证位置和速度边界连续；五次还能指定加速度边界，使加速度更平滑、冲击更小。它们只生成几何时间曲线，不自动保证碰撞、动力学或扭矩可行。

**Q：MoveIt 2 与 ros2_control 的关系？**  
A：MoveIt 负责规划和运动学；ros2_control 抽象硬件并管理控制器；JointTrajectoryController 执行时间化关节轨迹。Gazebo 和真机只是同一硬件抽象下的不同后端。

## 移动机器人

**Q：差速底盘的运动学？**  
A：由左右轮角速度换算线速度与角速度：`v=r(ωR+ωL)/2`，`ωz=r(ωR-ωL)/L`。该模型假设纯滚动无侧滑，真实地面需要用 IMU、雷达定位纠正。

**Q：SLAM 与定位的区别？**  
A：SLAM 同时建图和估计位姿；AMCL 在已有地图上定位。两者都需要可靠 odom、激光与 TF，SLAM 输出通常提供 `map->odom`。

**Q：EKF 为什么比直接用轮里程计好？**  
A：它将预测（轮速积分）和观测（IMU/GNSS/视觉）按噪声协方差融合；但错误的协方差和错误坐标系会使结果比单一传感器更差。

## 项目表达模板

“我将机械臂控制拆为算法、ROS 通信、模型和执行四层。底层 C++ 实现了状态管理、关节限幅、五次轨迹和 DLS 雅可比求解；在 ROS 2 中将速度指令转换为安全的关节轨迹。随后用 URDF/TF/RViz 验证状态闭环，并在 Gazebo Sim 中通过 `gz_ros2_control` 和 `JointTrajectoryController` 接入 MoveIt 2。真机阶段保持 MoveIt 接口不变，仅替换硬件后端为厂商驱动或 `SystemInterface`，并加入通信超时、软限位、急停和低速分级验证。”

> [!tip] 面试原则
> 讲清“你实际做了什么、如何验证、哪里仍是风险”。不要声称自定义 topic 闭环等同工业实时控制；主动说明要迁移到标准 action、真实反馈和硬件安全状态机，反而能体现工程判断。
