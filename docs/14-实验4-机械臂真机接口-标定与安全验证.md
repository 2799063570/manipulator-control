# 实验 4：机械臂真机接口、标定与安全验证

> [!danger] 授权与边界
> 仅在得到设备管理者授权、熟悉 AUBO 控制柜和厂商安全手册时执行。实体急停优先于软件急停；任何不明报警、坐标异常、反馈不可信时立即停止，回到只读诊断。

## 实验目标

让 MoveIt 轨迹经标准 controller 传给真机，且每一步可审计。首次不追求抓取成功，只追求读得对、停得住、动得小、能恢复。

## 阶段 A：网络与只读状态

记录 PC/控制柜 IP、端口、固件、驱动版本和网卡；敏感参数写入被 gitignore 的 local YAML。ping 通仅说明 IP 可达，不代表协议和运动许可可用。

启动厂商驱动的只读模式，禁止激活可写 controller。连续记录至少 60 秒的关节位置、速度、机器人模式、保护停、急停、通信延迟。将 6 轴 ROS 反馈与示教器逐一对照，检查 rad/deg（57.3 倍误差）、零位和正方向。六轴全部一致前绝不发运动命令。

## 阶段 B：安全链演练

在不运动状态下，分别触发实体急停、保护停、拔网线、退出 ROS、controller deactivate 和超限命令。对每例记录触发时间、驱动状态、ROS diagnostics、恢复步骤。正确行为是拒绝/停止，且运动许可不会自动恢复；恢复应当人工确认、清故障、重新 ready 后再激活控制器。

## 阶段 C：单轴低速

清空工作空间，人员站在急停旁，工具轻载或移除，速度和加速度限定为额定允许值的 5% 到 10%，一次最多动 0.05 到 0.1 rad。

1. 仅启动状态广播器和轨迹控制器。
2. 选一个远离限位的轴，发送 2 秒小动作后回原点。
3. 对比 action feedback 的 actual/desired/error、ROS joint_states 与示教器。
4. 对全部关节重复。任一轴反向时停机，在 URDF/驱动映射层修正，不能只在上层临时乘负号。

## 阶段 D：TCP、负载和手眼

TCP 是工具工作点相对法兰的位姿。多点法中，让工具尖端接触同一固定点，用多种腕姿记录法兰位姿，再求使所有反推工具点最一致的平移；用未参与计算的姿态验证误差。错误 TCP 会让笛卡尔路径整体偏移。

末端相机使用 eye-in-hand 标定，外置相机使用 eye-to-hand。采集姿态必须覆盖足够的旋转和平移，不能只小范围抖动；保存内参、外参、靶标和独立验证误差。工具质量和质心也必须录入控制柜，错误负载会影响重力补偿和保护阈值。

## 阶段 E：MoveIt 真实执行

先执行人工审查的 joint-space home 到 ready，再执行 2 到 5 cm 短笛卡尔直线，最后才做自动规划。每次核查当前反馈与 MoveIt start state 一致、planning scene 有桌子/工装、速度缩放仍低、路径没有靠近奇异或限位。

发生异常时：停机；保留 rosbag、驱动日志、控制柜日志和现场姿态；先离线复现，禁止现场反复“再试一次”。
