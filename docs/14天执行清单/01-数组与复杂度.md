## 1. 算法：两数之和

### 题意与约定

给定整数数组 `nums` 和目标值 `target`，找出两个**不同下标** `i`、`j`，使得 `nums[i] + nums[j] == target`，返回这两个下标。

这里按常见题设“存在且只需返回一组答案”实现。因此找到答案后立即 `return`；如果题目要求返回所有组合，则需要另行处理去重规则。

### 方法对比

| 方法 | 核心想法 | 时间复杂度 | 空间复杂度 | 适用性 |
|---|---|---:|---:|---|
| 暴力枚举 | 枚举所有 `i < j` 的组合 | `O(n²)` | `O(1)` | 最容易写对，适合小数据或用于校验 |
| 哈希表 | 遍历到 `x` 时查找此前是否见过 `target - x` | 平均 `O(n)` | `O(n)` | 通用解法，优先掌握 |
| 直接地址表 | 用数值本身作为数组下标 | `O(n)` | `O(U)` | 仅值域小、已知且非负时合适，`U` 为值域上界 |

### 1.1 暴力枚举

你的思路正确：双层循环枚举所有不同下标的组合。优化点是找到一组答案立刻返回，且用 `i + 1 < nums.size()` 避免手写 `size - 1` 时的边界陷阱。

```cpp
#include <vector>

std::vector<int> twoSumBruteForce(const std::vector<int>& nums, int target)
{
  for (std::size_t i = 0; i + 1 < nums.size(); ++i) {
    for (std::size_t j = i + 1; j < nums.size(); ++j) {
      if (nums[i] + nums[j] == target) {
        return {static_cast<int>(i), static_cast<int>(j)};
      }
    }
  }
  return {};
}
```

### 1.2 哈希表：推荐解法

你的“边查边存”是关键点，理解正确。先查找补数，再插入当前值，天然避免同一个元素被使用两次；例如 `[3]`、`target = 6` 不会错误返回 `[0, 0]`，而 `[3, 3]` 则会在处理第二个 `3` 时正确返回 `[0, 1]`。

```cpp
#include <unordered_map>
#include <vector>

std::vector<int> twoSumHash(const std::vector<int>& nums, int target)
{
  std::unordered_map<int, int> seen;  // 数值 -> 首次出现的下标

  for (std::size_t i = 0; i < nums.size(); ++i) {
    const int complement = target - nums[i];
    const auto it = seen.find(complement);
    if (it != seen.end()) {
      return {it->second, static_cast<int>(i)};
    }
    seen.emplace(nums[i], static_cast<int>(i));
  }
  return {};
}
```

注意：`unordered_map` 的平均查找复杂度是 `O(1)`，因此总时间通常写平均 `O(n)`；极端哈希冲突下可能退化。笔试中写“平均 `O(n)`”即可。

### 1.3 直接地址表：理解限制比记代码更重要

你已经发现两个核心问题：负数与越界。还需要补充三个问题：

1. 需同时检查补数下界：`0 <= target - value <= max_value`，只检查上界仍会访问负下标。
2. 不能先把所有值写入表后只遍历 `nums.size() / 2`；答案的两个元素可能都在数组后半段。
3. 不能把当前元素当作自己的配对；必须先查补数、再写当前下标，或额外检查下标不同。

下面是满足“元素都在 `[0, max_value]`”这个前提时的单遍正确写法：

```cpp
#include <vector>

std::vector<int> twoSumDirectAddress(
  const std::vector<int>& nums, int target, int max_value)
{
  if (max_value < 0) return {};

  std::vector<int> index(max_value + 1, -1);  // 值 -> 已见下标
  for (std::size_t i = 0; i < nums.size(); ++i) {
    const int value = nums[i];
    if (value < 0 || value > max_value) return {};  // 前提被破坏

    const int complement = target - value;
    if (0 <= complement && complement <= max_value && index[complement] != -1) {
      return {index[complement], static_cast<int>(i)};
    }
    index[value] = static_cast<int>(i);
  }
  return {};
}
```

结论：日常题目优先写哈希表。直接地址表只在值域明显小于数组长度、并且能保证范围时才更合适，例如计数排序、固定范围的离散状态表。

### 建议测试用例

| 输入 | `target` | 预期 | 验证点 |
|---|---:|---|---|
| `[2, 7, 11, 15]` | `9` | `[0, 1]` | 基本情况 |
| `[3, 3]` | `6` | `[0, 1]` | 重复元素、不同下标 |
| `[3]` | `6` | `[]` | 不可用同一元素两次 |
| `[]` | `0` | `[]` | 空输入 |
| `[-3, 4, 3, 90]` | `0` | `[0, 2]` | 负数；直接地址法不适用 |

## 2. C++：`vector`、引用与 `const`

### `vector` 的正确要点

`std::vector` 是连续存储的动态数组（顺序表）。常用初始化和复制写法：

```cpp
std::vector<int> v1(8, 9);                         // 8 个 9
std::vector<std::vector<int>> v2(3, std::vector<int>(2, 1));
std::vector<int> v3{1, 2, 3};                      // 列表初始化
std::vector<int> v4 = v3;                          // 深拷贝元素
std::vector<int> v5;
v5.assign(v4.begin(), v4.end() - 1);               // 复制前 n - 1 个元素
```

| 概念 | 含义 | 容易混淆的点 |
|---|---|---|
| `size()` | 当前元素数量 | `erase`、`pop_back`、`clear` 都会改变它 |
| `capacity()` | 已分配、可容纳的元素数量 | 删除元素通常**不**减少它 |
| `reserve(n)` | 提前确保容量至少为 `n` | 改变 capacity，不改变 size，不能用来访问新增元素 |
| `resize(n)` | 把元素数量改为 `n` | 改变 size；增长时会新增默认值或指定值 |

你的原笔记中“删除操作不会改变 size”这一句需要修正为：**删除操作会减少 `size()`，但通常不会自动减少 `capacity()`。** `shrink_to_fit()` 只是“请求”实现收缩容量，并不保证一定执行；它还可能重新分配和移动元素，不适合频繁调用。

`push_back` 在容量不足时可能触发重新分配，导致已有指针、引用和迭代器失效。若已知大概元素数量，可提前 `reserve()`，减少扩容次数；单次扩容代价可到 `O(n)`，但连续 `push_back` 的摊销复杂度通常仍为 `O(1)`。

### 引用与 `const`

“引用像别名”这个理解是对的，但“常量指针”不准确。引用不是指针：它必须在初始化时绑定对象，不能改为引用另一个对象，使用时不需要解引用符号。

```cpp
void incrementByValue(int x) { ++x; }       // 修改副本，调用者不变
void incrementByReference(int& x) { ++x; }  // 修改调用者对象
void print(const int& x) { /* x 只读 */ }  // 不复制，也不允许修改 x
```

`const std::vector<int>& nums` 的含义是“**以只读引用接收 nums**”：避免复制整段数组，同时在函数内防止误改调用者的数据。对本题这样只读、可能较大的容器参数，这是合适的默认选择。

## 4. ROS 2：node 与 topic

ROS 2 node 是负责单一逻辑职责的计算单元；一个进程可以包含一个或多个 node，因此 node 不等同于操作系统进程。

topic 是异步、发布订阅式、可多发布者和多订阅者的数据通道，适合持续状态或传感器流。它**不天然保证实时性**：实际延迟和可靠性还取决于 DDS、QoS、executor 调度、系统负载和网络。

| 命令 | 作用 | 今天需要看到什么 |
|---|---|---|
| `ros2 node list` | 列出当前 ROS graph 中可发现的 node | 至少记录一个 node 名称 |
| `ros2 topic list` | 列出当前 topic | 至少记录一个 topic 名称 |
| `ros2 topic info <topic> -v` | 查看类型、发布者、订阅者、QoS | 明天开始用于验证通信 |
