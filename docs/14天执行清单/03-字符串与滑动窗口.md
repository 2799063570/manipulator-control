## 题目一：有效的字母异位词

给定两个字符串 `s` 和 `t`，判断 `t` 是否是 `s` 的字母异位词。

字母异位词要求两个字符串的字符种类和每种字符的出现次数都相同，但字符的排列顺序可以不同。

### 方法一：固定大小的计数数组

若题目明确只包含小写英文字母，可以将字符映射到长度为 26 的数组下标。

```cpp
bool isValidAnagram(const string& s, const string& t)
{
    if (s.size() != t.size())
        return false;

    array<int, 26> count{};
    for (size_t i = 0; i < s.size(); ++i)
    {
        ++count[s[i] - 'a'];
        --count[t[i] - 'a'];
    }

    for (int value : count)
    {
        if (value != 0)
            return false;
    }
    return true;
}
```

这里 `s[i] - 'a'` 利用了小写字母的连续编码，将 `'a'` 到 `'z'` 映射为 `0` 到 `25`。时间复杂度为 O(n)，额外空间复杂度为 O(1)。该写法只适用于字符范围已知且为小写英文字母的题目。

### 方法二：哈希表计数

当字符集不局限于小写英文字母时，哈希表更通用。

```cpp
bool isValidAnagramHash(const string& s, const string& t)
{
    if (s.size() != t.size())
        return false;

    unordered_map<char, int> count;
    for (size_t i = 0; i < s.size(); ++i)
    {
        ++count[s[i]];
        --count[t[i]];
    }

    for (const auto& [character, value] : count)
    {
        if (value != 0)
            return false;
    }
    return true;
}
```

`unordered_map` 中不存在的键通过 `operator[]` 访问时会先创建，并以 `0` 初始化，因此可以直接递增或递减。平均时间复杂度为 O(n)，额外空间复杂度为 O(k)，其中 `k` 是不同字符的数量。

## 题目二：最长无重复子串

给定字符串 `s`，找出其中**不含重复字符的最长连续子串**的长度。

例如，`s = "abcabcbb"` 时，`"abc"`、`"bca"`、`"cab"` 都是不含重复字符的子串，最长长度为 `3`。

### 滑动窗口

使用左右指针维护一个连续窗口 `[left, right]`，并用计数器记录窗口内每个字符出现的次数。

1. 右指针向右移动，将新字符加入窗口。
2. 若该字符出现次数大于 1，说明窗口中出现重复字符；不断右移左指针并减少对应计数，直到窗口重新合法。
3. 每次窗口合法后，用窗口长度更新答案。

```cpp
int getMaxCharsLen(const string& chars)
{
    unordered_map<char, int> count;
    int answer = 0;

    for (int left = 0, right = 0;
         right < static_cast<int>(chars.size()); ++right)
    {
        ++count[chars[right]];

        while (count[chars[right]] > 1)
            --count[chars[left++]];

        answer = max(answer, right - left + 1);
    }
    return answer;
}
```

每个字符最多被左右指针各访问一次，因此时间复杂度为 O(n)，额外空间复杂度为 O(k)。当题目限定为小写英文字母时，也可将 `unordered_map<char, int>` 替换为 `array<int, 26>`；但通用字符串应使用哈希表，或按实际字符编码范围选择合适的数据结构。

注意：空字符串的答案应为 `0`，因此答案初值不能设为 `-1`。

## C++：`std::string`、范围 `for`、迭代器与 `string_view`

`std::string` 是管理字符序列的标准库类型，提供拼接、查找、截取等字符串操作。机器人开发中常用于处理 topic 名称、参数、文件路径和 `frame_id`。

范围 `for` 通常借助容器的 `begin()` 和 `end()` 遍历元素：

```cpp
for (auto value : nums)        // 按值遍历，会复制元素
{
}

for (auto& value : nums)       // 按引用遍历，可修改元素
{
}

for (const auto& value : nums) // 按常量引用遍历，不复制且不可修改
{
}
```

迭代器是用于遍历容器的抽象访问对象，常见用法与指针相似，但不等同于普通指针。`begin()` 指向第一个元素，`end()` 指向最后一个元素的下一个位置，`end()` 不能解引用。

`std::string_view`（C++17）是对一段已有字符数据的非拥有视图，传参时通常无需复制字符串。它可以理解为“数据起始位置加长度”的轻量描述；但不负责管理底层字符串的生命周期，因此不能在原字符串已经销毁后继续使用。

## OS：进程、线程与 ROS node

- 进程是正在运行的程序实例，拥有相对独立的地址空间和系统资源；不同进程通常通过 IPC、网络或 ROS 通信交换数据。
- 线程是进程内部的执行单元，同一进程内的线程共享大部分内存和资源，因此需要关注并发访问。
- ROS node 是 ROS 图中的逻辑计算单元，负责发布、订阅、服务等通信行为。一个进程可以包含一个或多个 node；一个 node 也可以在单线程或多线程执行器中运行，不能简单等同于一个进程或一个线程。

`SingleThreadedExecutor` 在调用 `spin()` 的线程中依次执行回调，不会让多个回调并行执行。`MultiThreadedExecutor` 可以使用多个工作线程并发处理可执行的回调；若回调共享可变数据，则仍需要使用互斥锁或其他同步机制。

```cpp
int main(int argc, char* argv[])
{
    rclcpp::init(argc, argv);

    auto node = std::make_shared<rclcpp::Node>("thread_test");
    rclcpp::executors::SingleThreadedExecutor executor;
    executor.add_node(node);
    executor.spin();  // 在当前线程等待并执行回调

    rclcpp::shutdown();
    return 0;
}
```

若主线程还要执行其他任务，可以将 `spin()` 放到独立线程中；结束前应取消执行器并等待该线程退出。

```cpp
int main(int argc, char* argv[])
{
    rclcpp::init(argc, argv);

    auto node = std::make_shared<rclcpp::Node>("thread_test");
    rclcpp::executors::MultiThreadedExecutor executor(
        rclcpp::ExecutorOptions(), 4);
    executor.add_node(node);

    std::thread spinner([&executor]() { executor.spin(); });

    while (rclcpp::ok())
    {
        // 主线程的其他任务
    }

    executor.cancel();
    spinner.join();
    rclcpp::shutdown();
    return 0;
}
```

| 对比项 | SingleThreadedExecutor | MultiThreadedExecutor |
| --- | --- | --- |
| 回调并行执行 | 否 | 可以 |
| 共享数据同步 | 较少涉及 | 通常需要考虑 |
| 调试难度 | 较低 | 较高 |
| 是否保证实时性 | 否 | 否；仍取决于系统、调度与整体设计 |

两种执行器都可以直接调用 `spin()`。只有当当前线程还需要承担其他工作时，才有必要将 `spin()` 放入 `std::thread`。

## ROS2：Service / Client

服务通信遵循“客户端发送请求，服务端处理请求并返回响应”的模式。一个服务端可以服务多个客户端；与持续发布的数据流相比，服务更适合一次性查询或命令确认。客户端 API 可以异步发送请求，但仍应处理服务不可用、超时和响应失败等情况。

```cpp
using AddTwoInts = example_interfaces::srv::AddTwoInts;

auto service = node->create_service<AddTwoInts>(
    "add_two_ints",
    [](const AddTwoInts::Request::SharedPtr request,
       AddTwoInts::Response::SharedPtr response)
    {
        response->sum = request->a + request->b;
    });
```

客户端应只调用一次 `async_send_request()`，并等待该次调用返回的 future：

```cpp
using AddTwoInts = example_interfaces::srv::AddTwoInts;

auto client = node->create_client<AddTwoInts>("add_two_ints");
auto request = std::make_shared<AddTwoInts::Request>();
request->a = 5;
request->b = 8;

auto future = client->async_send_request(request);
if (rclcpp::spin_until_future_complete(node, future) ==
    rclcpp::FutureReturnCode::SUCCESS)
{
    auto response = future.get();
    RCLCPP_INFO(node->get_logger(), "响应结果：%lld",
                static_cast<long long>(response->sum));
}
```

话题通信支持一个或多个发布者与订阅者，适合持续、异步的数据分发；服务通信支持请求和响应，适合需要明确处理结果的交互。选择时应根据数据是否持续产生、是否需要返回结果，以及失败和超时如何处理来判断。
