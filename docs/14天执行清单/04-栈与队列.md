## 有效的括号

给定一个只包括：

```
'('  ')'  '{'  '}'  '['  ']'
```

的字符串 `s`，判断字符串是否有效。
有效字符串满足：

1. 左括号必须用相同类型的右括号闭合。
2. 左括号必须以正确的顺序闭合。
3. 每个右括号都有一个对应的左括号。

### 错误记录（保留，用于复盘）

下面这版实现保留了原始错误：在未检查栈是否为空时调用了 `top()`。不要将它作为可用答案；后面的“发现的问题”和改进写法用于说明它为什么会出错。

```cpp
bool isValid_Stack(const string& chars)
{
    stack<char> judgment;
    unordered_map<char, char> map = {
        {'}', '{'},
        {']', '['},
        {')', '('}
};
    for (char c :  chars)
    {
        if (map.find(c) != map.end())
        {
            if (judgment.top() != map[c]) return false;// 隐患 栈可能为空
            judgment.pop();
        }
        else
        {
            judgment.push(c);
        }
    }
    // 可简化 judgment.empty();
    if (judgment.size() == 0) return true;
    return false;
}
```

### 复盘与改进

1. 当栈为空时调用 `judgment.top()` 属于未定义行为，可能崩溃，也可能表现为其他异常结果。
2. 变量名 `map` 会遮蔽 `std::map` 这个类型名；虽然能编译，但可读性较差，建议换为 `matching` 等名称。
3. 结尾可直接写成 `return judgment.empty();`。
4. 本题只有三类括号，使用 `switch` 通常比 `unordered_map` 更直观，也避免了不必要的哈希开销。

改进思路是：遇到左括号时，将其所期望的右括号压栈；遇到右括号时，先检查栈是否为空，再比较栈顶。

```cpp
switch(c)
{
case '(':
    judgment.push(')');
    break;

case '[':
    judgment.push(']');
    break;

case '{':
    judgment.push('}');
    break;

default:
    if(judgment.empty() || judgment.top()!=c)
        return false;

    judgment.pop();
}
```
### 错误思路（保留）

只统计各类括号的数量不能解决本题，因为计数法无法保证嵌套与闭合顺序。例如 `([)]` 中各种括号数量都匹配，但字符串无效。

# 最小栈（Min Stack）

## 题目描述

设计一个栈，支持：

1. `push(x)` —— 将元素 x 推入栈中
2. `pop()` —— 删除栈顶元素
3. `top()` —— 获取栈顶元素
4. `getMin()` —— 获取栈中的最小元素
要求每个操作的时间复杂度都为 O(1)。

```cpp
template <typename T>
class StackSelf
{
public:
    void push(T x)
    {
        nums_.push_back(x);
        if (mins_.empty() || x<mins_.back())
            mins_.push_back(x);
        else mins_.push_back(mins_.back());
    }
    void pop()
    {
        nums_.pop_back();
        mins_.pop_back();
    }
    T top()
    {
        return nums_.back();
    }
    T getMin()
    {
        return mins_.back();
    }
private:
    vector<T> nums_;
    vector<T> mins_;
};
```
核心思想是为每个入栈阶段保存对应的最小值。若只用一个变量记录最小值，那么最小值元素被弹出后就无法恢复前一阶段的最小值。这里的 `mins_` 与 `nums_` 始终同步：每压入一个元素，就压入当前阶段的最小值；每弹出一个元素，两个容器同时弹出。因此 `getMin()` 可以直接返回 `mins_.back()`。

## 每日温度（Daily Temperatures）
给定一个整数数组 `temperatures`，表示每天的温度。

请返回一个数组 `answer`，其中：

`answer[i]` 表示：

> 第 i 天之后，需要等待多少天，才会出现一个更高的温度。

如果之后没有更高温度，则等于0
```cpp
vector<int> getTemMaxDay(const vector<int>& tems)
{
    int size = tems.size();
    vector<int> nums(size, 0);
    if (tems.empty()) return nums;
    stack<pair<int, int>> temperatures;
    temperatures.push({tems[0], 0});
    for (int i = 1; i<size; i++)
    {
        while (!temperatures.empty() && tems[i] > temperatures.top().first)
        {
            nums[temperatures.top().second] = i - temperatures.top().second;
            temperatures.pop();
        }
        temperatures.push({tems[i], i});
    }
    return nums;

}
```
其实只存下标也是可以
```cpp
vector<int> getTemMaxDayIndex(const vector<int>& tems)
{
    int size = tems.size();
    vector<int> nums(size, 0);
    if (tems.empty()) return nums;
    stack<int> temperatures;
    temperatures.push(0);
    for (int i = 1; i<size; i++)
    {
        while (!temperatures.empty() && tems[i] > tems[temperatures.top()])
        {
            nums[temperatures.top()] = i - temperatures.top();
            temperatures.pop();
        }
        temperatures.push(i);
    }
    return nums;

}
```

栈中保存的是“尚未遇到更高温度”的日期。当前温度更高时，就依次结算并弹出所有比它低的日期。两种写法的时间复杂度均为 O(n)，因为每个下标最多入栈、出栈各一次；第二种只保存下标，更节省存储且信息已经足够。

- C++：`stack`、`queue`、`deque` 的用途与区别。

`stack` 表示后进先出（LIFO）的栈，常用于括号匹配、递归模拟和 DFS；`queue` 表示先进先出（FIFO）的队列，常用于 BFS；`deque` 是支持两端高效插入和删除的双端队列，也支持随机访问。

### 错误记录（保留）

“`deque` 是一种特别的 `vector`”这一说法不准确。两者是不同的容器：`vector` 通常使用连续内存，`deque` 通常采用分段连续的存储结构。保留这条错误记录，便于后续复盘。

`vector` 的随机访问通常更有缓存局部性；但在头部插入或删除元素往往需要移动后续元素。`deque` 更适合频繁的两端插入和删除，但其随机访问一般不如 `vector` 紧凑高效。

| 对比项 | `stack` | `queue` | `deque` |
| --- | --- | --- | --- |
| 抽象规则 | 后进先出 | 先进先出 | 两端操作 |
| 常用操作 | `push`、`pop`、`top` | `push`、`pop`、`front`、`back` | `push_front`、`push_back`、`pop_front`、`pop_back` |
| 随机访问 | 不提供 | 不提供 | 提供 |
| 底层实现 | 容器适配器，默认 `deque` | 容器适配器，默认 `deque` | 独立序列容器 |
| 典型场景 | 括号匹配、DFS | BFS、任务排队 | 单调队列、滑动窗口 |


- OS：互斥锁与死锁四个必要条件。
当多个线程可能同时读写同一份共享数据时，需要用互斥锁保护临界区，避免数据竞争。一个线程持有锁时，其他试图获取同一把锁的线程会等待；持锁线程离开临界区后，锁才会被释放。

为避免遗漏解锁操作，应使用 RAII。例如 `std::lock_guard<std::mutex> lock(mutex_);` 会在对象构造时加锁、在离开作用域时自动解锁，即使函数因异常提前退出也能释放锁。RAII 的常见应用包括锁管理、智能指针和文件资源管理。

死锁
死锁是我今天刚接触到的
就是一个线程，获取资源1，在等待资源2；另一个线程，获取资源2，在等待资源1
死锁有四个必要条件：互斥、占有、不可剥夺、循环等待
互斥即资源不共享
占有就是占有一个资源同时再请求另一个资源
不可剥夺是他的锁不能强制解锁
循环等待就是循环的等待

```cpp
class Robot
{

	std::mutex mutex_;
	Pose pose_;

public:

	void update(const Pose& new_pose)
	{
	    std::lock_guard<std::mutex> lock(mutex_);
	    pose_=new_pose;
	}
	Pose getPose()
	{
	    std::lock_guard<std::mutex> lock(mutex_);
	    return pose_;
	}
};
```
当一个线程已持有这把锁时，另一个尝试进入同一临界区的线程会等待。获取锁后，当前线程独占受保护资源；离开代码块时，`lock_guard` 自动释放锁。

死锁是多个线程互相等待对方持有的资源，导致所有相关线程都无法继续执行的状态。产生死锁需要同时满足四个条件：互斥、请求并保持、不可剥夺和循环等待。常见避免方式包括统一加锁顺序、使用 `std::lock` 同时获取多把锁，以及缩短临界区、减少锁的数量。

Action 用于处理持续时间较长、需要进度反馈或支持取消的任务。相较于 Service，Action 在一次任务中增加了 Goal、持续的 Feedback、最终的 Result 和取消请求（Cancel）四类交互。

### Action 客户端初稿：错误记录（保留）

以下初稿保留用于复盘，不能直接作为最终实现。它依赖全局 `feedback_index`，以 `sleep()` 控制流程，并在取消后很快停止执行器，可能来不及接收最终结果。

```cpp
#include "rclcpp/rclcpp.hpp"
#include "rclcpp_action/rclcpp_action.hpp"
#include "robot_control_ros2/action/fibonacci.hpp"


using Fibonacci = robot_control_ros2::action::Fibonacci;
using GoalHandle = rclcpp_action::Client<Fibonacci>::GoalHandle;

static int feedback_index  = 0;

class ActionClient : public rclcpp::Node
{
public:
    ActionClient() : Node("action_client")
    {
        client_ = rclcpp_action::create_client<Fibonacci>(this, "fibonacci_action");
    }
    void send_goal()
    {
        if(!client_->wait_for_action_server())
        {
            RCLCPP_ERROR(get_logger(), "Action Server不存在");
            return;
        }
        auto goal = Fibonacci::Goal();
        goal.order = 10;

        auto options = rclcpp_action::Client<Fibonacci>::SendGoalOptions();
        options.feedback_callback =
            [](auto goal_handle, auto feedback)
            {
                RCLCPP_INFO(rclcpp::get_logger("client"), "收到feedback -- %d", feedback->partial_sequence[feedback_index++]);
            };

        options.result_callback =
            [](const auto &result)
            {
                RCLCPP_INFO(rclcpp::get_logger("client"), "任务结束 result = %d", result.result->sequence[--feedback_index]);
            };
        options.goal_response_callback =
            [this](GoalHandle::SharedPtr goal_handle)
            {
                if(!goal_handle)
                {
                    RCLCPP_ERROR(get_logger(), "Goal rejected");
                    return;
                }
                RCLCPP_INFO(get_logger(), "Goal accepted");
                this->goal_handle_ = goal_handle;
            };

        client_->async_send_goal(goal, options);
    }
    void cancel_goal()
    {

        if(!goal_handle_)
        {
            RCLCPP_WARN(get_logger(), "没有正在执行的Goal");
            return;
        }
        client_->async_cancel_goal(goal_handle_, [](auto response)
            { RCLCPP_INFO(rclcpp::get_logger("client"), "cancel response received");}
        );
    }

private:
    rclcpp_action::Client<Fibonacci>::SharedPtr client_;
    GoalHandle::SharedPtr goal_handle_;
};


int main(int argc, char* argv[])
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<ActionClient>();
    rclcpp::executors::SingleThreadedExecutor executor;
    executor.add_node(node);
    std::thread spinner([&executor]()
    {
       executor.spin();
    });
    node->send_goal();

    sleep(6);
    node->cancel_goal();
    sleep(1);
    executor.cancel();

    if (spinner.joinable())
    {
        spinner.join();
    }
    return 0;
}
```
初稿还存在两个需要记住的问题：`feedback_index` 会跨任务共享状态，并可能因 `--feedback_index` 在尚未收到反馈时发生越界；`sleep()` 既阻塞又不便于与 ROS2 回调协作。保留初稿的目的，是对照理解为什么改进版要使用 Timer、GoalHandle 和结果回调。

### 客户端改进版

改进要点：

- 不使用全局 `feedback_index`；
- 使用成员变量保存 `GoalHandle`；
- 使用 Timer 代替 `sleep()`；
- 正确处理 Feedback、`WrappedResult` 与 Cancel；
- 在收到最终结果前保持执行器运行；
- 演示场景使用 `SingleThreadedExecutor` 已足够。
  ✅ 生命周期清晰

```cpp
#include "rclcpp/rclcpp.hpp"
#include "rclcpp_action/rclcpp_action.hpp"
#include "robot_control_ros2/action/fibonacci.hpp"
#include <chrono>
#include <memory>

using namespace std::chrono_literals;

using Fibonacci = robot_control_ros2::action::Fibonacci;
using GoalHandle = rclcpp_action::ClientGoalHandle<Fibonacci>;

class ActionClient : public rclcpp::Node
{
public:
    ActionClient() : Node("fibonacci_action_client")
    {
        client_ = rclcpp_action::create_client<Fibonacci>(
                this,
                "fibonacci_action"
            );
        // 6秒后自动取消Goal
        cancel_timer_ =
            this->create_wall_timer(
                6s,
                std::bind(&ActionClient::cancel_goal, this)
		    );
    }
    void send_goal()
    {

        if(!client_->wait_for_action_server())
        {
            RCLCPP_ERROR( get_logger(), "Action Server不存在");
            return;
        }

        Fibonacci::Goal goal;
        goal.order = 10;
        rclcpp_action::Client<Fibonacci>::SendGoalOptions options;

        /*
         * Goal响应
         */
        options.goal_response_callback =
        [this](GoalHandle::SharedPtr goal_handle)
        {
            if(!goal_handle)
            {
                RCLCPP_ERROR(get_logger(),"Goal被拒绝");
                return;
            }
            RCLCPP_INFO(get_logger(),"Goal被接受");
            goal_handle_ = goal_handle;
        };
        /*
         * Feedback
         */
        options.feedback_callback =
	        [](GoalHandle::SharedPtr,
	           const std::shared_ptr<const Fibonacci::Feedback> feedback)
        {
            std::string output;
            for(auto value : feedback->partial_sequence)
            {
                output += std::to_string(value) + " ";
            }
            RCLCPP_INFO(rclcpp::get_logger("client"),"Feedback: %s",
	            output.c_str());
        };
        /*
         * Result
         */
        options.result_callback =
        [this](const GoalHandle::WrappedResult & result)
        {
            switch(result.code)
            {
            case rclcpp_action::ResultCode::SUCCEEDED:

                RCLCPP_INFO(get_logger(),"Action执行成功");
                for (auto value : result.result->sequence)
                {
                    RCLCPP_INFO(get_logger(), "result = %d", value);
                }
                break;

            case rclcpp_action::ResultCode::CANCELED:

                RCLCPP_WARN(get_logger(), "Action被取消");
                break;

            case rclcpp_action::ResultCode::ABORTED:

                RCLCPP_ERROR(get_logger(),"Action执行失败");
                break;

            default:

                RCLCPP_ERROR(get_logger(), "未知状态");
                break;
            }
            // Result收到以后关闭Timer
            cancel_timer_->cancel();
            // 程序退出
            rclcpp::shutdown();
        };
        client_->async_send_goal(goal, options);
    }

private:

    void cancel_goal()
    {
        if(!goal_handle_)
        {
            RCLCPP_WARN(get_logger(), "没有活动Goal");
            return;
        }
        RCLCPP_WARN(get_logger(), "发送Cancel请求");
        client_->async_cancel_goal(goal_handle_);
    }

    rclcpp_action::Client<Fibonacci>::SharedPtr client_;
    GoalHandle::SharedPtr goal_handle_;
    rclcpp::TimerBase::SharedPtr cancel_timer_;
};

int main(int argc, char ** argv)
{

    rclcpp::init(argc, argv);
    auto node = std::make_shared<ActionClient>();

    node->send_goal();
    rclcpp::spin(node);
    rclcpp::shutdown();

    return 0;
}
```

### Action 服务端初稿：错误记录（保留）

下面这版服务端保留为复盘材料。其中 `feedback->partial_sequence.push_back(i)` 生成的是递增整数序列，并不是真正的 Fibonacci 序列；此外，直接 `detach()` 线程会增加节点销毁时的生命周期风险。

```cpp
#include "rclcpp/rclcpp.hpp"
#include "robot_control_ros2/action/fibonacci.hpp"
#include "rclcpp_action/rclcpp_action.hpp"

using Fibonacci = robot_control_ros2::action::Fibonacci;
using GoalHandle = rclcpp_action::ServerGoalHandle<Fibonacci>;

class ActionServer : public rclcpp::Node
{
public:
    ActionServer() : Node("action_server")
    {
        server_ = rclcpp_action::create_server<Fibonacci>(
            this, "fibonacci_action",
            [this](const rclcpp_action::GoalUUID& uuid,
                std::shared_ptr<const Fibonacci::Goal> goal)
            { return this->handle_goal(uuid, goal); },

            [this](const std::shared_ptr<GoalHandle> goal_handle)
            { return this->handle_cancel(goal_handle); },

            [this](const std::shared_ptr<GoalHandle> goal_handle)
            { this->handle_accept(goal_handle); }
        );
    }
private:
    rclcpp_action::Server<Fibonacci>::SharedPtr server_;
    rclcpp_action::GoalResponse handle_goal(
        const rclcpp_action::GoalUUID& uuid,
        std::shared_ptr<const Fibonacci::Goal> goal)
    {
        RCLCPP_INFO(this->get_logger(), "get goal order = %d", goal->order);
        return rclcpp_action::GoalResponse::ACCEPT_AND_EXECUTE;
    }
    rclcpp_action::CancelResponse handle_cancel(
        const std::shared_ptr<GoalHandle> goal_handle)
    {
        RCLCPP_INFO(this->get_logger(), "get cancel request");
        return rclcpp_action::CancelResponse::ACCEPT;
    }
    void handle_accept(const std::shared_ptr<GoalHandle> goal_handle)
    {
        std::thread(&ActionServer::execute, this, goal_handle).detach();
    }

    void execute(const std::shared_ptr<GoalHandle> goal_handle)
    {
        auto feedback = std::make_shared<Fibonacci::Feedback>();
        auto result = std::make_shared<Fibonacci::Result>();
        int order = goal_handle->get_goal()->order;
        for (int i = 0; i<order; i++)
        {
            if (goal_handle->is_canceling())
            {
                RCLCPP_INFO(this->get_logger(), "任务取消");
                goal_handle->canceled(result);
                return;
            }
            feedback->partial_sequence.push_back(i);

            goal_handle->publish_feedback(feedback);
            RCLCPP_INFO(this->get_logger(), "发送feedback");

            std::this_thread::sleep_for(
                std::chrono::seconds(1)
            );
        }
        result->sequence =
            feedback->partial_sequence;
        goal_handle->succeed(result);
        RCLCPP_INFO(
            get_logger(),
            "任务完成"
        );
    }
};

int main(int argc, char* argv[])
{
    rclcpp::init(argc, argv);
    rclcpp::spin(std::make_shared<ActionServer>());
    rclcpp::shutdown();

    return 0;
}
```
### 服务端改进版

改进版修复了 Fibonacci 生成逻辑，补充了参数校验、取消处理、异常终止与明确的结果状态，结构也更接近常见的 Action Server 组织方式。

> 复盘提示：下方示例虽然比初稿更完整，但仍使用了 `std::thread(...).detach()`。因此“避免裸 `detach` 风险”这一原始结论不成立：若节点在工作线程结束前销毁，仍可能产生生命周期问题。生产代码应由对象持有并在析构时 `join()` 工作线程，或采用受控线程池/执行器管理任务。

```cpp
#include "rclcpp/rclcpp.hpp"
#include "rclcpp_action/rclcpp_action.hpp"

#include "robot_control_ros2/action/fibonacci.hpp"

#include <thread>
#include <chrono>
#include <functional>
#include <memory>


using namespace std::chrono_literals;


using Fibonacci =
    robot_control_ros2::action::Fibonacci;


using GoalHandle =
    rclcpp_action::ServerGoalHandle<Fibonacci>;



class ActionServer : public rclcpp::Node
{

public:

    ActionServer()
    : Node("fibonacci_action_server")
    {

        server_ =
            rclcpp_action::create_server<Fibonacci>(
                this,
                "fibonacci_action",


                // Goal callback
                std::bind(
                    &ActionServer::handle_goal,
                    this,
                    std::placeholders::_1,
                    std::placeholders::_2
                ),


                // Cancel callback
                std::bind(
                    &ActionServer::handle_cancel,
                    this,
                    std::placeholders::_1
                ),


                // Accepted callback
                std::bind(
                    &ActionServer::handle_accept,
                    this,
                    std::placeholders::_1
                )
            );


        RCLCPP_INFO(
            get_logger(),
            "Fibonacci Action Server Started"
        );

    }



private:


    /*
     * 1. 收到Goal请求
     *
     * 作用：
     * 判断是否接受任务
     */
    rclcpp_action::GoalResponse handle_goal(
        const rclcpp_action::GoalUUID&,
        std::shared_ptr<const Fibonacci::Goal> goal)
    {


        RCLCPP_INFO(
            get_logger(),
            "Receive goal order=%d",
            goal->order
        );


        // 参数检查
        if(goal->order <= 0)
        {

            RCLCPP_WARN(
                get_logger(),
                "Invalid order"
            );


            return rclcpp_action::GoalResponse::REJECT;
        }



        return rclcpp_action::GoalResponse::ACCEPT_AND_EXECUTE;

    }



    /*
     * 2. 收到Cancel请求
     *
     * 这里只决定是否允许取消
     */
    rclcpp_action::CancelResponse handle_cancel(
        const std::shared_ptr<GoalHandle>)
    {


        RCLCPP_INFO(
            get_logger(),
            "Receive cancel request"
        );


        return rclcpp_action::CancelResponse::ACCEPT;

    }



    /*
     * 3. Goal接受后
     *
     * 创建执行线程
     */
    void handle_accept(
        const std::shared_ptr<GoalHandle> goal_handle)
    {


        std::thread(
            &ActionServer::execute,
            this,
            goal_handle
        ).detach();


    }



    /*
     * 4. 真正执行任务
     */
    void execute(
        const std::shared_ptr<GoalHandle> goal_handle)
    {


        RCLCPP_INFO(
            get_logger(),
            "Start executing goal"
        );



        auto feedback =
            std::make_shared<Fibonacci::Feedback>();


        auto result =
            std::make_shared<Fibonacci::Result>();



        int order =
            goal_handle
            ->get_goal()
            ->order;



        int a = 0;
        int b = 1;



        try
        {

            for(int i=0;i<order;i++)
            {


                /*
                 * 检查取消
                 */
                if(goal_handle->is_canceling())
                {

                    RCLCPP_WARN(
                        get_logger(),
                        "Goal canceled"
                    );


                    goal_handle->canceled(result);

                    return;

                }



                /*
                 * 生成Fibonacci
                 */
                feedback->partial_sequence.push_back(a);



                /*
                 * 发布feedback
                 */
                goal_handle->publish_feedback(
                    feedback
                );


                RCLCPP_INFO(
                    get_logger(),
            "Publish feedback size=%zu",
                    feedback->partial_sequence.size()
                );



                int next = a+b;

                a=b;

                b=next;



                std::this_thread::sleep_for(
                    1s
                );

            }


            /*
             * 正常完成
             */
            result->sequence =
                feedback->partial_sequence;


            goal_handle->succeed(result);



            RCLCPP_INFO(
                get_logger(),
                "Goal succeed"
            );


        }


        catch(const std::exception & e)
        {

            RCLCPP_ERROR(
                get_logger(),
                "Exception: %s",
                e.what()
            );


            goal_handle->abort(result);

        }


    }



private:


    rclcpp_action::Server<Fibonacci>::SharedPtr server_;

};



int main(
    int argc,
    char ** argv)
{


    rclcpp::init(
        argc,
        argv
    );


    auto node =
        std::make_shared<ActionServer>();


    rclcpp::spin(node);


    rclcpp::shutdown();


    return 0;

}
```

ServerGoalHandle是ROS2 Action Server用于管理单个Goal生命周期的句柄对象。它封装了客户端发送的Goal信息，并提供发布Feedback、返回Result、处理Cancel以及查询Goal状态等接口。Action Server通常在线程中持有该Handle，在执行任务过程中通过它与客户端交互。

ROS2 Action Server通过create_server创建，包含三个回调：Goal回调负责决定是否接受任务，Cancel回调处理取消请求，Accepted回调启动任务执行。实际任务一般在线程中执行，执行过程中通过publish_feedback发布反馈，完成后通过succeed、abort或者canceled返回Result。

ROS2 Action Client 不能直接发送 cancel，它必须先保存 `GoalHandle`。因为一个 Action Server 可能同时管理多个 Goal，取消请求必须明确指定取消哪一个 Goal。`async_cancel_goal()` 发送取消请求，Server 通过 `handle_cancel()` 接收，然后执行线程通过 `is_canceling()` 停止任务。

`handle_cancel()` 虽然最终只返回 ACCEPT/REJECT，但是它需要 `goal_handle` 来识别被取消的具体 Goal，并根据任务状态决定是否允许取消。真正停止任务通常不在 handle_cancel 中完成，而是在 execute() 线程中通过 `goal_handle->is_canceling()` 检测后执行。
