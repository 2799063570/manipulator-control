## 二叉树遍历

原稿列出了树遍历任务，但没有记录具体实现。下面补充三个最小版本，复习时要先说清楚：**访问根节点的时机决定遍历顺序**。

```cpp
struct TreeNode
{
    int val;
    TreeNode* left = nullptr;
    TreeNode* right = nullptr;
};
```

### 前序遍历：根 → 左 → 右（递归）

函数含义：将以 `root` 为根的子树按前序追加到 `result` 中。递归出口是 `root == nullptr`。

```cpp
void preorderRecursive(TreeNode* root, vector<int>& result)
{
    if (root == nullptr)
        return;

    result.push_back(root->val);
    preorderRecursive(root->left, result);
    preorderRecursive(root->right, result);
}
```

时间复杂度为 O(n)，递归调用栈空间为 O(h)，其中 `h` 是树高。

### 前序遍历：根 → 左 → 右（迭代）

栈是后进先出。为让左子树先被访问，需要先压入右孩子，再压入左孩子。

```cpp
vector<int> preorderIterative(TreeNode* root)
{
    vector<int> result;
    if (root == nullptr)
        return result;

    stack<TreeNode*> nodes;
    nodes.push(root);

    while (!nodes.empty())
    {
        TreeNode* current = nodes.top();
        nodes.pop();
        result.push_back(current->val);

        if (current->right != nullptr)
            nodes.push(current->right);
        if (current->left != nullptr)
            nodes.push(current->left);
    }
    return result;
}
```

### 层序遍历：按层从左到右（迭代）

层序遍历使用队列。每次记录当前队列长度，这个长度就是当前层的节点数；处理完这批节点后，再进入下一层。

```cpp
vector<vector<int>> levelOrder(TreeNode* root)
{
    vector<vector<int>> result;
    if (root == nullptr)
        return result;

    queue<TreeNode*> nodes;
    nodes.push(root);

    while (!nodes.empty())
    {
        const int levelSize = static_cast<int>(nodes.size());
        vector<int> level;
        level.reserve(levelSize);

        for (int i = 0; i < levelSize; ++i)
        {
            TreeNode* current = nodes.front();
            nodes.pop();
            level.push_back(current->val);

            if (current->left != nullptr)
                nodes.push(current->left);
            if (current->right != nullptr)
                nodes.push(current->right);
        }
        result.push_back(std::move(level));
    }
    return result;
}
```

### 复盘检查

- 空树必须直接返回，不能访问 `root->val`。
- 迭代前序中若先压左、再压右，实际访问顺序会变成根 → 右 → 左。
- 层序遍历的 `levelSize` 必须在进入本层循环前固定；否则新加入的下一层节点也会被混入当前层。
- 测试：空树、单节点、只有左孩子、只有右孩子、满二叉树。

## C++：三类智能指针与循环引用

- `unique_ptr` 表示独占所有权，不能复制，只能通过 `std::move()` 转移所有权，适合唯一拥有资源的对象。
- `shared_ptr` 通过强引用计数支持共享所有权；最后一个 `shared_ptr` 释放后，所管理对象被销毁。
- `weak_ptr` 只观察由 `shared_ptr` 管理的对象，不增加强引用计数。通过 `lock()` 可尝试取得 `shared_ptr`；若对象已销毁，得到空指针。

循环引用发生在两个对象相互持有 `shared_ptr` 时：即使外部所有者都已离开，双方仍让对方的引用计数大于 0，导致对象无法析构。通常让“观察者”或反向关联使用 `weak_ptr` 来打破环。

```cpp
struct Child;

struct Parent
{
    shared_ptr<Child> child;
};

struct Child
{
    weak_ptr<Parent> parent;  // 不参与强引用计数，避免 Parent <-> Child 成环
};
```

复盘问题：谁真正拥有对象？谁只需要观察对象？前者才适合 `shared_ptr` 或 `unique_ptr`，后者通常应使用原始指针、引用或 `weak_ptr`，具体取决于生命周期是否需要被检查。

## OS：条件变量与生产者—消费者

生产者—消费者模型通过共享缓冲区传递数据。互斥锁保护队列和结束标志等共享状态；条件变量让消费者在“队列为空且尚未结束”时阻塞，状态改变后由生产者通知。

```cpp
#include <condition_variable>
#include <iostream>
#include <mutex>
#include <queue>
#include <thread>

std::queue<int> queue;
std::mutex mutex;
std::condition_variable cv;
bool finished = false;

void producer()
{
    for (int i = 0; i < 10; ++i)
    {
        {
            std::lock_guard<std::mutex> lock(mutex);
            queue.push(i);
        }
        cv.notify_one();
    }

    {
        std::lock_guard<std::mutex> lock(mutex);
        finished = true;
    }
    cv.notify_all();
}

void consumer()
{
    while (true)
    {
        std::unique_lock<std::mutex> lock(mutex);
        cv.wait(lock, [] { return !queue.empty() || finished; });

        if (queue.empty() && finished)
            return;

        const int value = queue.front();
        queue.pop();
        lock.unlock();

        std::cout << "consume " << value << '\n';
    }
}
```

`cv.wait(lock, predicate)` 会在谓词不满足时释放锁并等待；被唤醒后重新获取锁、再次检查谓词，因此可以应对虚假唤醒。把打印等耗时操作移到解锁后，可缩短临界区。

### 错误记录（保留）：只依赖哨兵值的退出方式

原始示例以 `value == 9` 作为消费者退出条件。对“一个生产者、一个消费者、且 9 一定是最后一条数据”的演示是可行的；但若存在多个消费者，只有一个线程能拿到哨兵，其余线程会永久等待。上面的 `finished` 方案更容易扩展；也可为每个消费者投放一个哨兵值。

## ROS2 工程：`package.xml` 与 `CMakeLists.txt`

`package.xml` 描述功能包元信息和依赖关系；`CMakeLists.txt` 描述具体构建步骤。两者必须对应：代码使用了某个 ROS2 包，通常需要在 `package.xml` 声明依赖，并在 `CMakeLists.txt` 中 `find_package()` 后传给目标。

以一个使用 `rclcpp` 和 `sensor_msgs` 的可执行文件为例：

```cmake
find_package(ament_cmake REQUIRED)
find_package(rclcpp REQUIRED)
find_package(sensor_msgs REQUIRED)

add_executable(sensor_node src/sensor_node.cpp)
ament_target_dependencies(sensor_node rclcpp sensor_msgs)

install(TARGETS sensor_node
  DESTINATION lib/${PROJECT_NAME})

ament_package()
```

`package.xml` 中至少应有对应的运行/构建依赖声明，例如：

```xml
<depend>rclcpp</depend>
<depend>sensor_msgs</depend>
```

构建流程为：源码经 CMake 配置与编译生成可执行文件，`install()` 规则将其安装到工作区的 `install/` 目录；执行 `source install/setup.bash` 后，ROS2 才能通过 `ros2 run <package> sensor_node` 找到它。
