# 当前代码类与 ROS 2 接口逐项解析

## 1. `RobotState`

文件：`robot_control/include/robot_state.hpp`、`src/robot_state.cpp`。

职责：保存自由度 dof、关节位置 q、速度 dq。它是插值器、限幅器、轨迹缓存共同使用的值对象。正确使用顺序：构造时确定 dof；设置 position/velocity 前校验数组长度；读取前校验索引；和另一状态比较前确保 dof 一致。

易错：把目标状态当实际反馈；用 `==` 判断浮点是否到位；没有定义时间戳。工程中应添加近似比较、时间戳与有效位，并让真实 `/joint_states` 成为 current state 的唯一来源。

## 2. `SafetyLimiter`

文件：`safety_limiter.hpp/.cpp`。

职责：保存各关节 lower/upper limit、max velocity，检查或 clamp `RobotState`。建议在三个位置调用：接收上层目标时（快速拒绝）；生成轨迹后（防算法错误）；写入硬件前（最后软件保护）。但最后一道真正保护仍是控制柜/驱动器和硬件急停。

易错：所有关节用同一个最大速度；单位混用 degree/radian；只 clamp 目标位置而不限制轨迹中的速度/加速度；clamp 后未告诉上层目标已被改写。

## 3. `CubicInterpolator`

文件：`cubic_interpolator.hpp/.cpp`。

接口语义：`setStateStart`、`setStateGoal` 设置边界；`calculate3Times` 和 `calculate5Times` 生成离散 `RobotState` 序列；`getTrajectory` 读取序列。三次/五次中的“3/5”是多项式阶数，不是三个/五个采样点。

易错：duration 小于 dt 导致轨迹点不足；未清除上次轨迹；忽略峰值速度/加速度；将 timer 周期与插值 dt 配成不同却不做重采样。建议记录生成点数、首末状态、最大 q/dq/ddq，并在目标更新时重新从反馈状态规划。

## 4. `TrajectoryBuffer`

文件：`trajectory_buffer.hpp/.cpp`。

职责：队列化轨迹点，提供 push、pop、hasNext、clear、size。它模拟控制器命令缓存。多线程版本必须为 push/pop 加同步；当前单线程 callback+timer 虽通常在单线程 spin 内顺序执行，但更换 executor 后不一定安全。

易错：空队列 pop；新目标不清旧队列；生产速度大于消费速度导致延迟越来越大；以旧目标而非当前反馈作为新轨迹起点。

## 5. `JacobianSolver`

文件：`jacobian_solver.hpp/.cpp`。

`solvePseudoInverse(J,b)` 求最小二乘/最小范数解；`solveDampedLeastSquares(J,b,lambda)` 在奇异附近更稳定；`conditionNumber` 用奇异值衡量病态程度。输入维度必须满足 J 的列数等于关节数、b 的维度等于 J 的行数；lambda 必须大于零且按任务调节。

易错：把 J 的行列写反；用未归一单位把米/秒与弧度/秒混在一起；只看求解成功不看输出速度；忽略奇异附近的方向丢失。生产系统应把 condition number、最小奇异值、速度缩放发布到 diagnostics。

## 6. `Vel2PosNode`

文件：`robot_control_ros2/src/vel_to_pos_node.cpp`，参数在 `config/vel_to_pos.yaml`。

流程：订阅 `joint_velocity_cmd`；以 duration 推算 position goal；经 SafetyLimiter；以五次插值放入 buffer；timer 按 control_rate 取点并发布 `joint_position_cmd`。参数 `dof`、`max_velocity`、`lower_limits`、`upper_limits`、`control_rate`、`velocity_cmd_time`、`dt` 必须相互一致。

现存学习代码风险：日志硬编码访问 6 个关节；消息数组长度未经检查；重复设置 position；内部 start/goal 未从真实反馈更新；连续命令没有明确抢占策略；高频 INFO 会影响实时性。将其看作算法教学节点，最终执行改接标准 trajectory controller 或 MoveIt Servo。

## 7. `joint_position_cmd_to_states`

文件：`robot_control_ros2/src/joint_position_cmd_to_states.cpp`。

它把自定义位置命令转为 `/joint_states`，使 RViz 可显示。它不计算动力学、不读编码器、不代表真实执行器反馈。因此 Gazebo/真机运行时应让 `JointStateBroadcaster` 发布状态，关闭/隔离这个教学转发节点，避免两个 publisher 同时发布 `/joint_states`。

## 8. Launch 文件的职责

`simple_arm_gazebo/gazebo.launch.py` 负责仿真底座：GZ、clock bridge、robot_state_publisher、spawn、controller spawner。`demo_gazebo.launch.py` 在此基础启动 move_group 和 RViz。launch 中 `Command([xacro ...])` 运行 Xacro，并把字符串作为 robot_description 参数。排错时把 Command 单独复制到命令行展开，最容易发现 Xacro 变量/路径错误。

## 9. 自定义消息与标准接口的映射

| 当前接口 | 适用阶段 | 工程替代 |
|---|---|---|
| `JointVelocityCmd` | 算法学习 | `TwistStamped` + MoveIt Servo，或 controller velocity interface |
| `JointPositionCmd` | RViz 闭环 | `trajectory_msgs/JointTrajectory` / FollowJointTrajectory |
| 手动 `/joint_states` | 无硬件模型显示 | JointStateBroadcaster/真实硬件反馈 |
| 手动 TF broadcaster | 学习 TF | robot_state_publisher 与 state estimation |
