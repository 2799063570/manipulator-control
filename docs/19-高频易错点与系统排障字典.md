# 高频易错点与系统排障字典

## 通用排障原则

不要凭界面猜。每次只验证一层，并保留证据：`ros2 node list` 看进程；`ros2 topic list -t` 看类型；`ros2 topic info -v` 看连接和 QoS；`ros2 topic echo/hz` 看内容频率；`view_frames` 看 TF；最后才看 RViz/Gazebo 行为。遇到问题先从下游往上游查“状态是否真实到达”。

## 1. 构建与环境

| 现象 | 根因 | 排查/修复 |
|---|---|---|
| 找不到 package | 没 source 当前 install，或 workspace 未 build | `source /opt/ros/.../setup.bash` 后 `source install/setup.bash` |
| 代码改了不生效 | source 了旧 overlay，或没有重编 C++ | `colcon build --packages-select 包名`，重新 source |
| CMake 找不到 Eigen | 未安装/未声明依赖 | 安装 libeigen3-dev，并在 CMake/package.xml 声明 |
| Python launch import 报错 | ROS 发行版/API 混用 | 用当前发行版的 package，避免复制 Jazzy/Ironic 示例 |
| 同名包行为异常 | 多个 overlay 含同名包 | `ros2 pkg prefix 包名` 检查实际被加载路径 |
| RViz/Setup Assistant 创建窗口失败 | Wayland 与 OGRE/GLX 不兼容 | `QT_QPA_PLATFORM=xcb` 启动；仍失败加 `LIBGL_ALWAYS_SOFTWARE=1`，长期使用 Xorg |

## 2. URDF/Xacro

| 现象 | 常见原因 | 解决 |
|---|---|---|
| RViz 看不到模型 | `robot_description` 未发布、mesh URI 错 | 单独 xacro 展开，`check_urdf`，检查 `package://` |
| 关节不动 | joint_states name 与 URDF 不同 | 比对名字、大小写、namespace |
| 模型姿态怪异 | origin rpy/xyz、joint axis 错 | 固定一个关节逐个检查，遵循 x 前 y 左 z 上 |
| Gazebo 飞走/抖动 | 质量为零、惯量不正定、初始穿模 | 加合理 inertial，简化 collision，移开重叠 |
| MoveIt 规划穿物体 | 只有 visual 没 collision，或 scene 未同步 | 为所有障碍补 collision，Gazebo 和 PlanningScene 双写 |

特别易错：STL 常无单位信息。很多 CAD 导出为毫米，但 ROS 使用米；模型若大 1000 倍，碰撞、惯量、相机距离都会错。导入后在 RViz 用已知尺寸尺量核对。

## 3. TF 与时间

| 现象 | 根因 | 修复 |
|---|---|---|
| `Extrapolation into the future/past` | 时间戳不一致、use_sim_time 混用 | 仿真所有相关节点设 use_sim_time=true，检查 /clock |
| `No transform` | TF 树断开或 frame 拼错 | `view_frames`，检查 `frame_id` 和静态 TF |
| TF 多重父节点 | 多个节点发布同一 child | 只保留一个发布者，例如 EKF 或 diff drive 二选一发布 odom TF |
| map 跳动 | 把 SLAM/AMCL 的 map->odom 和 odom->base 混了 | 固定职责：SLAM/AMCL 发 map->odom，EKF 发 odom->base |

仿真最常见问题是启动节点没有传 `use_sim_time`，它用墙钟订阅来自仿真时钟的消息，导致 TF 查找失败。任何新 launch 节点都要明确这个参数。

## 4. ros2_control 和 Gazebo

| 现象 | 优先检查 | 常见根因 |
|---|---|---|
| controller 未 active | `ros2 control list_controllers` | plugin/YAML 路径错、关节名错、硬件接口未导出 |
| interface unavailable | `list_hardware_interfaces` | URDF ros2_control 少 command/state interface |
| action goal rejected | controller 日志 | joint_names 顺序/名称错误、时间不递增、超限 |
| 执行跟踪误差大 | feedback、控制频率、物理参数 | state 没反馈、PID/接口类型不当、惯量不合理 |
| 无 `/joint_states` | broadcaster 状态 | 未 spawn JointStateBroadcaster，或两个 publisher 冲突 |

不要混淆 Gazebo Classic 和 Gazebo Sim：Classic 常见 `gazebo_ros_pkgs`、`libgazebo_ros_*`；Gazebo Sim 常见 `ros_gz_sim`、`ros_gz_bridge`、`gz_ros2_control`。二者插件 filename、world 格式、bridge 都不同。

## 5. MoveIt

| 现象 | 原因 | 检查 |
|---|---|---|
| Plan 成功但 Execute 失败 | controller action 映射错 | moveit_controllers.yaml、action list、controller active |
| Pose 目标无解 | 工作空间外、tip/base 配错、IK 插件差 | 先试 Joint 目标，检查 SRDF chain/kinematics.yaml |
| Start state out of bounds | 当前 joint state 缺失或超限 | echo joint_states，检查时间和 limit |
| 自碰撞过多 | collision mesh/禁用对不合理 | Setup Assistant 后人工审查碰撞矩阵 |
| 路径绕得很远 | 采样规划随机性/约束/环境 | 增加 planning time，换 RRTConnect/PRM，核对障碍 |

常见误区：MoveIt 能在 RViz 动，不代表真机在动；RViz 可能只是显示 planned trajectory。必须看 action feedback 和真实 joint_states。

## 6. 差速底盘、SLAM、Nav2

| 现象 | 根因 | 修复顺序 |
|---|---|---|
| 前进变后退 | wheel axis/符号/左右名反了 | 先悬空测轮子，再改接口层符号 |
| odom 直行漂 | 轮径不准、轮子打滑、编码器错 | 校准轮径，检查编码器，再融合 IMU |
| 转角不准 | 轮距不准 | 原地多圈试验校轮距 |
| 地图重影 | TF/时间错、激光外参错、odom 漂 | 先 TF 和 scan，再校 odom，最后调 SLAM |
| Nav2 撞障碍 | footprint 太小、costmap 没 scan | 检查 footprint、observation_sources、inflation |
| Nav2 不动 | 目标未定位、cmd_vel 被 mux 拦截 | 看 AMCL、/plan、/cmd_vel、twist_mux 状态 |

## 7. 真机的致命易错点

1. **deg 与 rad**：打印数值无意义，必须同示教器逐轴对照。
2. **单位缩放**：m/mm、rad/s/RPM、编码器脉冲/圈、减速比和四倍频常常同时错。
3. **错误初始状态**：控制器刚激活就将目标 0 发送给实际不在 0 的机械臂，会突跳；activate 前应读反馈并 hold 当前位姿。
4. **假反馈**：用命令回填 joint_states 会掩盖执行器没动、反向或卡住的问题。
5. **重复控制源**：遥控、导航、脚本同时发 cmd_vel，或两个 controller 抢同一接口；用 twist_mux 和 controller claim 检查。
6. **无通信超时**：网线断开仍保持旧速度是不可接受的；MCU 和 ROS 两层都需 timeout。
7. **软件急停当硬件急停**：进程死锁、断电、网络故障时软件无法保证执行，必须有物理安全链。

## 8. 最小诊断命令卡

```bash
ros2 node list
ros2 topic list -t
ros2 topic info /scan -v
ros2 topic echo /joint_states --once
ros2 topic hz /odom
ros2 control list_hardware_interfaces
ros2 control list_controllers
ros2 action list -t
ros2 run tf2_tools view_frames
ros2 bag record /tf /tf_static /joint_states /scan /odom /cmd_vel /diagnostics
```
