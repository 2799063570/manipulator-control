# 十月机器人开发求职：笔试准备计划

> 目标：在 10 月开始投递机器人软件/机器人控制/运动规划/ROS 开发岗位前，建立一套可以在限时笔试中稳定输出的能力，同时把现有项目沉淀为可讲、可演示、可验证的作品。

## 1. 先定范围：笔试准备的优先级

机器人开发岗位的笔试通常不是只考 ROS。最值得优先准备的是下面四层；前两层决定能否通过通用笔试，后两层决定能否在机器人专项笔试和技术面中拉开差距。

| 优先级 | 模块 | 要达到的状态 | 典型考察 |
|---|---|---|---|
| P0 | C++ 与数据结构算法 | 中等难度题可在 45 分钟内独立写出、编译通过并说明复杂度 | 数组/链表、栈队列、二叉树、哈希、二分、双指针、DFS/BFS、动态规划 |
| P0 | 操作系统、Linux、网络基础 | 能解释线程同步、内存、进程通信与常用 Linux 排障 | 进程线程、锁、死锁、虚拟内存、TCP/UDP、Shell、CMake |
| P1 | 机器人基础 | 能手推简单模型并讲清工程含义 | 坐标变换、FK/IK、Jacobian、奇异性、轨迹、PID、滤波、卡尔曼 |
| P1 | ROS 2 与工程化 | 能按数据流定位故障、写出小型节点和 launch | topic/service/action、QoS、TF、URDF、ros2_control、MoveIt2、日志与测试 |

### 岗位方向与取舍

先用“机械臂 ROS 2 控制与仿真”作为主线，不要同时把移动机器人、嵌入式、视觉、强化学习都学到同等深度。投递时可覆盖以下相近岗位：

- 机器人软件开发 / ROS 开发：重点是 C++、Linux、ROS 2、系统集成。
- 机械臂控制 / 运动规划：在上述基础上强化运动学、轨迹、MoveIt 2、ros2_control。
- 移动机器人软件：补强定位、建图、Nav2、传感器融合，但不取代主线。

不建议把“会运行仿真”当作目标。笔试与面试更看重：知道输入输出、关键假设、故障边界和验证方法。

## 2. 从现在到 10 月的三阶段节奏

以下按每周 **15–20 小时** 设计；如果可投入时间更少，优先保证 P0 和每周一次限时题。

| 阶段      | 时间           | 重点                                   | 阶段验收                                                          |
| ------- | ------------ | ------------------------------------ | ------------------------------------------------------------- |
| 基础补齐    | 现在至 8 月中旬    | C++、算法核心题型、Linux/OS；恢复并理解现有 ROS 2 工程 | 40 道高质量算法题；能从零写 ROS 2 发布订阅节点；完成一次项目启动与排障记录                    |
| 专项联结    | 8 月中旬至 9 月中旬 | 机器人数学、ROS 2、控制与规划；把知识点连到仓库代码         | 能手推 2 自由度 FK/Jacobian；解释 MoveIt → 控制器 → 硬件数据流；完成一个可复现的机械臂闭环演示 |
| 冲刺与投递准备 | 9 月中旬至 10 月  | 真题模拟、错题回炉、项目表达、简历投递                  | 每周 2 场模拟笔试；形成项目 README、演示视频和 90 秒自我介绍；开始按岗位定制投递               |

### 每周固定模板

| 时间块 | 建议内容 | 产出 |
|---|---|---|
| 3 次 × 90 分钟 | 算法限时训练：读题、编码、边界、复盘 | 3 道题的题解与错误标签 |
| 2 次 × 90 分钟 | C++/OS/Linux 专题 | 一页知识卡或一个可运行小实验 |
| 2 次 × 2 小时 | 机器人与 ROS 项目实践 | commit、截图、日志或测试结果 |
| 1 次 × 2 小时 | 模拟笔试或综合复盘 | 分数、耗时、薄弱点、下周调整 |

## 3. 12 周可执行清单

### 第 1–2 周：建立算法与 C++ 底座

- 算法：数组、字符串、哈希表、双指针、二分、栈与队列。每类至少 3 题，先写暴力解再优化。
- C++：RAII、智能指针、左值/右值、引用与指针、`const`、STL 容器复杂度、迭代器失效。
- 工程：熟悉 `g++`、`gdb`、`cmake`、`git diff`、`rg`；为每题写 3–5 个边界测试。
- 验收：45 分钟完成一道“数组/哈希 + 边界处理”中等题；能解释 `vector` 扩容和 `unordered_map` 冲突。

### 第 3–4 周：树图、并发与 Linux

- 算法：链表、二叉树、递归、DFS/BFS、堆/优先队列、排序；开始整理模板，但不机械背诵。
- OS：进程与线程、用户态/内核态、虚拟内存、互斥锁/条件变量、死锁条件、生产者消费者。
- Linux/网络：文件权限、进程排障、管道与 socket 基础、TCP 三次握手/重传、TCP 与 UDP 取舍。
- 验收：能写线程安全的生产者消费者最小示例；能说清控制循环中为什么避免动态内存、锁竞争与阻塞 I/O。

### 第 5–6 周：机器人数学与控制

- 坐标变换：旋转矩阵、齐次变换、欧拉角与四元数的优缺点、坐标系链式变换。
- 机械臂：FK、IK、多解/无解、Jacobian、速度映射、奇异性与 DLS。
- 控制：PID 的作用与局限、限幅、轨迹插值、采样周期、低通滤波与离散实现。
- 项目连接：阅读并运行仓库中的轨迹插值、Jacobian 伪逆/DLS 相关代码，记录“公式—代码—测试”的对应关系。
- 验收：手推平面 2R 机械臂末端位置和 Jacobian；用自己的话解释奇异位形的风险和至少三种应对策略。

### 第 7–8 周：ROS 2 与机械臂工程链路

- ROS 2：node、topic、service、action、parameter、launch、namespace、remap、QoS 兼容性。
- 模型与状态：URDF/Xacro、`robot_state_publisher`、`joint_states`、TF tree。
- 执行链：`ros2_control`、controller manager、JointTrajectoryController、FollowJointTrajectory、Gazebo 与真机后端的差异。
- MoveIt 2：碰撞模型、IK、规划、时间参数化、执行与常见失败原因。
- 验收：画出并口述 `MoveIt → FollowJointTrajectory → JointTrajectoryController → 硬件接口 → joint_states → TF` 的闭环；遇到不动、无 TF、无数据时能按底层到上层排查。

### 第 9–10 周：综合项目与专项题

- 完成并录制一个 2–3 分钟演示：机械臂模型加载、关节状态、MoveIt 规划、Gazebo 执行；若真机条件具备，只做安全的只读验证或按项目安全规程分级测试。
- 为项目补一页说明：架构图、启动命令、关键模块、一个排障案例、当前限制和下一步改进。
- 做 2 次机器人专项自测：运动学/控制计算题 + ROS 2 问答 + C++ 编程题。
- 验收：不看稿完成项目 90 秒介绍，并能回答“为什么不用 service 执行轨迹”“仿真到真机还差什么”“QoS 不兼容如何定位”。

### 第 11–12 周：模拟笔试与投递材料

- 每周两次 90–120 分钟模拟：一次通用 C++/算法，一次机器人专项；严格断网、计时、提交后复盘。
- 建立错题本，按“不会知识点 / 思路不完整 / 代码 bug / 边界遗漏 / 时间管理”分类；同类问题连续出现两次就安排专题回炉。
- 准备一页简历和项目链接，按岗位关键词调整技能顺序。投递前核对每一项都能讲出具体实现与验证证据。
- 验收：连续两次模拟达到目标岗位的及格线；至少准备 30 个高频问答和 6 个可量化项目故事。

## 4. 笔试知识清单

### C++：优先掌握而不是泛学

| 主题 | 必会问题 |
|---|---|
| 内存与对象 | 栈/堆区别；RAII；智能指针的所有权；浅拷贝与深拷贝；Rule of Zero/Three/Five |
| 现代 C++ | move 的用途；完美转发的使用场景；lambda 捕获；`auto`/`decltype`；模板与编译期错误 |
| STL | `vector`、`deque`、`list`、`map`、`unordered_map` 的复杂度与适用场景；迭代器失效 |
| 并发 | mutex、lock_guard、unique_lock、condition_variable、atomic 的区别；死锁规避 |
| 工程质量 | 编译链接区别；静态库/动态库；异常边界；单元测试；日志等级 |

### 算法：按模式练习

先建立“题型 → 模板 → 边界”的映射。每道题复盘时都要回答：输入为空怎么办？下标是否越界？重复元素怎么办？复杂度是多少？

| 模式 | 识别信号 | 最低练习量 |
|---|---|---|
| 哈希、双指针、滑动窗口 | 查找、去重、连续子数组/子串 | 12 题 |
| 二分与排序 | 单调性、最小/最大可行值 | 8 题 |
| 链表、栈、队列 | 反转、环、括号、单调栈 | 10 题 |
| 树与图 | 层序、路径、连通性、拓扑 | 15 题 |
| 堆与贪心 | Top K、合并、区间选择 | 8 题 |
| 动态规划与回溯 | 最优子结构、组合、排列 | 12 题 |

> 建议：题量目标约 65 题，其中至少 45 题要二刷；二刷比不断刷新题更能提高笔试稳定性。

### 机器人专项：能够“计算 + 解释 + 落地”

- 坐标与运动学：坐标系、旋转与齐次变换、DH 的基本含义、FK/IK、Jacobian、奇异性。
- 轨迹与控制：三次/五次插值、速度/加速度/jerk 约束、PID、前馈、采样与滤波。
- 感知与定位：编码器里程计误差、IMU、EKF 基本思想、SLAM 与 AMCL 的分工。
- 规划：配置空间、碰撞检测、RRT/RRTConnect 的直觉、局部与全局规划、代价地图。
- 系统：实时性边界、通信延迟、状态机、安全限位、急停、仿真与真机差异。

现有资料可对应查阅：`20-面试八股题库-背诵版.md` 用于口述，`11-实验1-轨迹规划-限幅与雅可比控制.md` 用于数学与代码，`22-MoveIt与ros2_control加载执行全流程.md` 用于系统链路，`26-ROS2-QoS详解与机器人通信配置.md` 用于通信题。

## 5. 每次算法题的标准流程

1. **读题（5 分钟）**：写出输入、输出、约束和一个反例；不要立即编码。
2. **设计（10 分钟）**：先说明朴素解，再给优化思路和目标复杂度。
3. **编码（20–30 分钟）**：函数短小，变量名反映语义；避免凭感觉复制模板。
4. **自测（5–10 分钟）**：至少覆盖空输入、单元素、重复、极值、越界五类情况。
5. **复盘（10 分钟）**：记录卡点和最终复杂度；24 小时后不看答案重写一次。

推荐的 C++ 笔试提交检查：

```text
[ ] 是否包含空指针、空数组、长度为 1 的处理？
[ ] 循环边界是否与区间定义一致？
[ ] int 是否可能溢出，需要 long long 吗？
[ ] unordered_map 的 key 是否正确？
[ ] 时间复杂度、空间复杂度能否说清？
[ ] 如果题目要求标准输入输出，是否移除了调试输出？
```

## 7. 项目如何服务于笔试和面试

把项目准备成“可被追问的证据”，而不是仅列技术名词。

| 项目事实 | 可以证明的能力 | 准备的证据 |
|---|---|---|
| 2 自由度机械臂轨迹与 Jacobian 控制 | C++、运动学、数值稳定性 | 公式、关键类、测试用例、奇异点处理说明 |
| Gazebo + ros2_control + MoveIt 2 闭环 | ROS 2 系统集成与接口理解 | 架构图、启动步骤、Action 链路、演示录屏 |
| AUBO 模型/真机接口准备 | 工程安全与仿真到真机意识 | 只读验证、限位/超时、分级测试清单 |
| 移动底盘模型与后续 Nav2 | TF、定位、传感器融合基础 | `map-odom-base_link` 图、标定与排障笔记 |

项目表述必须区分“已完成”和“计划中”。例如：已在仿真中验证 MoveIt 轨迹执行；真机部分仍按只读反馈、低速单轴、标定、短轨迹的安全门禁推进。诚实的边界比夸大经历更经得住追问。

## 8. 9 月下旬开始投递前的门槛

满足以下大部分条件即可开始投递；不必等到所有知识点完全学完。

- [ ] 65 道算法题完成，45 道可在不看答案的情况下重写。
- [ ] 近 4 次模拟笔试中，至少 3 次能在规定时间内完成基础题并留出检查时间。
- [ ] 能解释常见 C++、OS、ROS 2 和机器人问题，遇到不会的问题能说清推理路径。
- [ ] 有一个可运行、可录屏的机械臂项目，并有清晰 README。
- [ ] 简历中每一个技术关键词都对应具体代码、命令、测试或排障案例。
- [ ] 准备好 90 秒项目介绍、一个失败/排障故事和一个工程安全故事。

## 9. 第一周从今天开始做什么

1. 建一个个人错题本，使用本文模板。
2. 完成数组/哈希/双指针各 2 题，每题限时 45 分钟并二刷。
3. 复习 C++ 的 RAII、智能指针、`vector` 与 `unordered_map`，各写 3 句自己的解释。
4. 在本仓库复现一个已有 ROS 2 示例，记录启动命令、数据流和一个故障排查点。
5. 周末做一次 100 分钟小模拟，并据结果决定下一周最需要补的一个模块。

> 核心原则：用“限时输出 + 复盘 + 项目验证”替代只看教程。10 月开始找工作并不要求现在全会；要求的是每周都能量化地减少薄弱点，并持续留下能证明能力的作品和记录。
