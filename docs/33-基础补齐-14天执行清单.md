## 0. 先准备好工作台（第 0 天，60–90 分钟）

建立一个自己的目录或笔记页，不追求漂亮，只保留下面四张表：

```text
job-prep/
├── algorithm-log.md       # 题目、耗时、错因、二刷日期
├── cpp-linux-notes.md     # 每天 3–5 条自己的解释
├── ros-lab.md             # 命令、现象、数据流、排障记录
└── weekly-review.md       # 本周得分、下周唯一优先项
```

算法题尽量统一用 C++ 完成。每道题保存为一个独立 `.cpp` 文件，并且保留至少 3 个测试用例；不要只在网页编辑器里提交一次就结束。

每天的最低投入是 **2.5 小时**；时间够时再扩展到 4 小时。

> [!important] ROS 2 的练习应在项目使用的 Ubuntu 24.04 + ROS 2 Jazzy 环境中进行。若当前主要使用 Windows，算法/C++ 练习可在 Windows 完成；涉及 `colcon`、Gazebo、RViz 的步骤切换到已配置好的 Ubuntu、双系统或 WSL2 图形环境，避免混用终端环境导致无意义排障。

| 时段 | 最低动作 | 时长 |
|---|---|---|
| 算法 | 1 道新题 + 1 道旧题二刷 | 75 分钟 |
| C++/Linux | 一个小主题，写自己的解释或极小程序 | 45 分钟 |
| ROS 2 / 项目 | 一个教程动作或一次工程观察 | 60 分钟 |

## 1. 两周完成标准

两周结束时检查以下结果，而不是检查“看了多少小时视频”。

- [ ] 完成 14 道新算法题，其中至少 6 道能不看答案二刷。
- [ ] 给每一道题写了复杂度与边界测试；错题有明确的错误类型。
- [ ] 能解释 RAII、智能指针、`vector` 扩容、`map` 与 `unordered_map` 的取舍。
- [ ] 能说出进程/线程、互斥锁/条件变量、TCP/UDP 的核心区别。
- [ ] 能在一个新 ROS 2 包中写 C++ 发布者和订阅者，编译、运行、用 CLI 验证。
- [ ] 完成一次已有项目启动观察：记录节点、topic、`/joint_states`、TF、控制器的状态或报错。

## 2. 第 1 周：先形成“写得出来”的感觉

### 第 1 天：数组与复杂度

- 算法：两数之和；写暴力解 `O(n²)` 后再写哈希解 `O(n)`。
- C++：复习 `vector`、引用、`const`；回答“为什么函数参数有时传 `const vector<int>&`？”
- Linux：会用 `pwd`、`ls -la`、`cd`、`mkdir -p`、`rg`、`git status`。
- ROS：阅读并运行 ROS 2 的 node/topic 入门教程；用 `ros2 node list`、`ros2 topic list` 看系统。
- 验收：向自己口述哈希解为什么更快，以及它多付出了什么空间代价。

### 第 2 天：双指针

- 算法：有序数组两数之和、移除元素；限时各 30 分钟。
- C++：指针、引用和空指针；写一个函数分别以值、引用、指针修改整数，观察差异。
- Linux：`find`、`rg --files`、`rg "pattern" path`；只搜索本仓库的 C++ 与 launch 文件。
- ROS：完成 C++ publisher/subscriber 教程，运行后用 `ros2 topic echo <topic>` 验证数据。
- 验收：写下“发布者是谁、订阅者是谁、消息类型是什么、如何确认消息真的到达”。

### 第 3 天：字符串与滑动窗口

- 算法：有效的字母异位词、最长无重复子串；第二题卡住 20 分钟后可看提示，但必须自己重写。
- C++：`std::string`、`string_view`（知道用途即可）、范围 `for`、迭代器。
- OS：进程与线程分别是什么；机器人系统里“节点”和“线程”不是同一个概念。
- ROS：完成 service/client 教程；分别说出 topic、service 的适用场景。
- 验收：画出本次 service 请求与响应的箭头图。

### 第 4 天：栈与队列

- 算法：有效括号、最小栈或每日温度（二选一）。
- C++：`stack`、`queue`、`deque` 底层特点与适用场景；不要把 `vector`、`list`、`deque` 混为一谈。
- OS：互斥锁解决什么问题；死锁四个必要条件。
- ROS：完成 action 教程，理解 goal、feedback、result、cancel。
- 验收：能回答“执行机械臂轨迹为什么更适合 action 而不是 service”。

### 第 5 天：二分与排序

- 算法：二分查找、搜索插入位置；统一使用左闭右闭区间 `[left, right]`，写清循环不变量。
- C++：`std::sort`、比较器、lambda；写一个按第二个字段排序的 `vector<pair<int,int>>`。
- Linux：`ps`、`top` 或 `htop`、`kill` 的意义；只在测试进程上操作。
- ROS：学习 parameter 与 launch；将发布频率做成参数。
- 验收：代码中不改源文件，只通过参数改变发布频率。

### 第 6 天：链表

- 算法：反转链表、链表是否有环。
- C++：对象生命周期、构造/析构、RAII；写一个打开文件后由析构函数关闭的最小包装类，理解即可。
- OS：虚拟内存为什么存在；栈与堆在程序里的角色。
- ROS：创建自己的最小 C++ 包（不要复制整个工程），包含一个 publisher、一个 subscriber。
- 验收：完成 `colcon build`，然后 source 工作区并运行两个节点。

### 第 7 天：第 1 次小模拟与复盘

- 90 分钟模拟：两道旧题或同型新题（60 分钟）+ 10 个 C++/OS/ROS 口述题（20 分钟）+ 自检（10 分钟）。
- 复盘：每道错题只归入一类：知识缺口、思路不完整、代码 bug、边界遗漏、时间管理。
- 项目：打开本仓库 [实验 0](10-实验0-ROS2基础与现有控制代码复现.md)，选择一个已有节点或 launch 文件，记录它启动后出现的节点和 topic。
- 验收：写一页周报：本周题数、正确率、最常见错误、下周只优先修复的一项。

## 3. 第 2 周：把基础连到工程

### 第 8 天：哈希与 STL 取舍

- 算法：两数之和二刷 + 字母异位词分组。
- C++：`map` 与 `unordered_map`：有序性、复杂度、哈希冲突、何时选择哪一个。
- ROS：运行 `ros2 topic info -v <topic>`，认识发布者/订阅者和 QoS。
- 验收：针对一个具体 topic，写下它的消息类型、发布者、订阅者、QoS。

### 第 9 天：树的遍历

- 算法：二叉树前序遍历、层序遍历；递归版和迭代版至少会一种。
- C++：`unique_ptr`、`shared_ptr`、`weak_ptr` 的所有权关系；重点理解循环引用为何需要 `weak_ptr`。
- OS：条件变量与生产者消费者；知道 `while` 等待条件而不是 `if` 的原因。
- 项目：阅读 `robot_control_ros2` 中一个 `CMakeLists.txt` 与一个 `package.xml`，写出依赖、可执行文件和安装规则的对应关系。
- 验收：能用三句话说清一个 ROS 2 C++ 包如何从源码变为可 `ros2 run` 的程序。

### 第 10 天：图搜索

- 算法：岛屿数量（DFS/BFS）、课程表（拓扑排序，先理解概念）。
- C++：`mutex`、`lock_guard`、`unique_lock` 的区别；只需会常见用法，不追求复杂无锁编程。
- ROS：学习 TF；运行 `robot_state_publisher` 相关示例，使用 `ros2 run tf2_tools view_frames` 生成 TF 图。
- 验收：说清 `base_link`、关节 frame、世界 frame 的父子关系；一个 child frame 为什么不能有两个 parent。

### 第 11 天：堆与优先队列

- 算法：数组中的第 K 个最大元素或合并 K 个有序链表（二选一）。
- C++：`priority_queue` 默认是大顶堆；写出小顶堆的声明。
- 网络：TCP 与 UDP 的取舍；说明激光雷达高频数据与关键控制事件可能选择不同通信策略的原因。
- 项目：运行或阅读二维机械臂的启动文件，记录 URDF、`joint_states`、RSP、TF 的数据流。
- 验收：画出 `joint_states → robot_state_publisher → TF → RViz`。

### 第 12 天：动态规划入门

- 算法：爬楼梯、打家劫舍；每题先写状态定义和状态转移再编码。
- C++：移动语义只理解使用场景：大对象转移所有权时避免不必要拷贝；不要死背实现细节。
- ROS：阅读 QoS；人为设置一个不兼容场景或阅读已有文档中的排障案例。
- 验收：回答“topic 能看到但收不到数据”时的三步排查。

### 第 13 天：机器人控制基础连接

- 算法：任选本周最差的一类重做 2 题。
- 机器人：阅读 [实验 1](11-实验1-轨迹规划-限幅与雅可比控制.md) 中的轨迹插值与 Jacobian 部分；手写 `xdot = J(q) qdot` 的每个量代表什么。
- C++：查看相关实现，定位“输入、输出、限幅/异常处理”所在位置。
- 验收：用 60 秒说明“为什么奇异位形附近要限速或使用 DLS”。

### 第 14 天：第 2 次小模拟 + 项目排障记录

- 100 分钟模拟：两道算法（60 分钟）+ C++/OS/ROS/机器人简答（30 分钟）+ 检查（10 分钟）。
- 项目：选一个可启动的仿真或最小节点，执行下列观察命令并记录输出或失败现象：

```bash
ros2 node list
ros2 topic list
ros2 topic echo /joint_states --once
ros2 topic info /joint_states -v
ros2 run tf2_tools view_frames
```

- 排障记录至少包括：目标、启动命令、预期现象、实际现象、检查命令、根因或下一步假设。
- 验收：完成两周复盘，并为第 3 周选出一个短板专题，不超过一个。

## 4. 算法题记录模板

每次写完立即填，不要等周末回忆。

```markdown
## 题目：
- 日期：
- 分类：哈希 / 双指针 / 二分 / 栈队列 / 链表 / 树图 / 堆 / DP
- 限时：__ 分钟；实际：__ 分钟；是否独立完成：是 / 否
- 最终复杂度：时间 __；空间 __
- 边界测试：空输入 / 单元素 / 重复值 / 极值 / 其他
- 错误类型：知识缺口 / 思路 / 实现 bug / 边界 / 时间管理
- 一句话根因：
- 二刷日期：明天、7 天后
```

## 5. 卡住时的规则

- 算法题：独立思考 20 分钟；再看题目提示，不直接看完整代码；之后关掉答案自己写完。
- ROS 工程：先看节点、topic、消息、TF，再看 RViz；不要一开始反复点击 Execute。
- C++ 概念：先写 20 行最小示例验证，再看长篇解释。
- 一天没完成：第二天只补“最小动作”，不要把所有欠账堆到周末。

## 6. 两周后如何进入下一阶段

第 3–4 周保持每天一新一旧算法题，新增树图、堆和 DP；ROS 线转向 `URDF → joint_states → TF → ros2_control`。当能稳定完成基础题且能说清机械臂状态链路后，再进入运动学、轨迹和 MoveIt 2 的专项联结阶段。
