# Wheeltec Robot 功能包分类与学习路线

> 适用对象：使用 Jetson Nano 运行 ROS 1（Noetic 风格）Wheelec 移动机器人的学习者。
>
> 源码工作区：`D:\files\code\wheeltec_robot\src`。本文不要求一次编译或运行全部功能包；应以“底盘可控、数据可见、建图可用、导航闭环”为主线逐层验证。

## 1. 先建立整体认识

这个工作区由三类内容组成：

1. **轮趣针对实车定制的包**：底盘串口、车体模型、雷达与相机选择、启动编排、跟随、语音和竞赛行为。这是学习和修改的重点。
2. **第三方设备驱动**：雷达、深度相机、IMU、ZED、RealSense 等。按实际硬件选用，不需要全部安装和启动。
3. **ROS 社区算法包**：SLAM、导航、定位、局部规划等。原则上先理解输入输出和配置，再阅读内部实现。

机器人运行的数据链路如下：

```text
底盘控制板 ──串口──> wheeltec_robot_node ──> /odom、/imu、/PowerVoltage、TF
                                      ^
                                      └────────────── /cmd_vel

雷达 ──> /scan ──> SLAM 或定位 ──> /map、map→odom TF
相机 ──> 图像话题 ──> 识别/跟随/交互 ──> /cmd_vel
导航目标 ──> move_base ──> /cmd_vel
```

`/cmd_vel` 是需要最谨慎对待的话题：发布它就可能让真实底盘运动。首次测试请架空车轮或保持急停可用。

## 2. 功能包分层分类

### A. 平台与硬件抽象层（第一优先级）

| 包/目录 | 核心职责 | 应先掌握的接口 |
|---|---|---|
| `turn_on_wheeltec_robot` | 整个实车的核心包。串口读写底盘控制板，统一组织底盘、TF、导航、建图、相机和雷达启动。 | 订阅 `/cmd_vel`；发布 `/odom`、`/imu`、`/PowerVoltage` 和 TF。 |
| `fdilink_ahrs` | 飞迪 IMU/GNSS/RTK 驱动。 | `imu`、`/gps/fix`、`/mag_pose_2d`、`/NED_odometry`。 |
| `robot_pose_ekf` | 融合轮式里程计、IMU、视觉里程计的 EKF。 | 输入 odom/IMU，输出融合姿态与 TF。 |
| `wheeltec_robot_rc` | 键盘/手柄遥控与速度平滑。 | 关注它最终发出的 `/cmd_vel`。 |
| `wheeltec_joy_control`（包名 `wheeltec_joy`） | 手柄数据读取、按键映射和控制。 | `joy_node`、`joycontrol`。 |

建议先阅读：

- `turn_on_wheeltec_robot/launch/include/base_serial.launch`：串口设备名、波特率、坐标系和里程计修正参数；
- `turn_on_wheeltec_robot/src/wheeltec_robot.cpp`：`/cmd_vel` 如何编码成串口帧，以及底盘数据如何转成 `/odom`、`/imu`；
- `turn_on_wheeltec_robot/launch/turn_on_wheeltec_robot.launch`：不同底盘型号和功能开关的总入口。

### B. 传感器驱动层（按实际硬件选择）

| 设备类别 | 包 | 用途 |
|---|---|---|
| 镭神 2D 雷达 | `lslidar_driver`、`lslidar_msgs`、`lslidar` | M10/M10P/N10 等雷达的串口/网络驱动。 |
| 思岚 2D 雷达 | `rplidar_ros` | A1/A2/A3/S1/S2 等雷达驱动。 |
| 乐动 2D 雷达 | `ldlidar_14`、`ldlidar_19` | LD14、LD06、LD19 雷达驱动。 |
| 奥比中光 RGB-D | `astra_camera`（目录 `ros_astra_camera`） | Astra、Dabai、Gemini 的彩色、深度、点云和相机内参。 |
| 普通 RGB USB 相机 | `usb_cam` | V4L2 摄像头图像采集。 |
| RealSense | `realsense2_camera`、`realsense2_description` | D400/T265/L515 等相机驱动与模型。 |
| ZED 双目 | `zed_wrapper`、`zed_nodelets`、`zed_interfaces`、`zed_ros` | 双目图像、深度、点云、位姿及自定义接口。 |
| 浏览器视频 | `web_video_server` | 将 ROS 图像话题转为浏览器视频流。 |

统一入口是 `turn_on_wheeltec_robot/launch/wheeltec_lidar.launch` 和 `wheeltec_camera.launch`。学习时只选择车上真实安装的一种雷达和一种相机，避免多个驱动竞争同一个 USB/串口设备。

### C. 建图、定位与导航层（第二优先级）

| 子系统 | 包 | 作用 |
|---|---|---|
| 2D SLAM | `slam_karto`、`open_karto`、`sparse_bundle_adjustment` | Karto 建图与图优化。工程启动文件还可调用系统安装的 gmapping、hector、cartographer。 |
| 深度转雷达 | `depthimage_to_laserscan` | 用深度图生成 `LaserScan`，便于接入 2D 导航栈。 |
| 自主探索 | `rrt_exploration` | 发现未知区域前沿，基于 RRT 选择探索目标，支持多机器人。 |
| 定位 | `amcl` | 在保存好的静态地图中估计机器人位姿。 |
| 地图 | `map_server` | 读取 YAML/PGM 地图并提供地图服务。 |
| 导航协调 | `move_base` | 接收导航目标，协调路径规划、代价地图和恢复行为。 |
| 代价地图 | `costmap_2d`、`voxel_grid` | 将地图和传感器障碍物转为全局/局部代价地图。 |
| 全局规划 | `global_planner`、`navfn`、`carrot_planner` | 从当前位置到目标点生成全局路径。 |
| 局部避障 | `teb_local_planner`、`dwa_local_planner`、`base_local_planner` | 根据障碍物和运动学约束输出安全速度。工程默认优先使用 TEB。 |
| 恢复与接口 | `nav_core`、`clear_costmap_recovery`、`rotate_recovery`、`move_slow_and_clear`、`fake_localization` | 插件接口、故障恢复与仿真辅助。 |
| 元包 | `navigation` | ROS 导航栈的聚合包，本身不是单独的核心节点。 |

这层的必备输入是：

```text
/scan       雷达扫描
/odom       底盘里程计
/imu        IMU（推荐）
TF          至少连通 map → odom → base_footprint → laser
/map        建图过程的实时地图，或 map_server 加载的静态地图
```

### D. 视觉理解与行为层（第三优先级）

| 包 | 用途 |
|---|---|
| `simple_follower` | 激光跟随、RGB-D 跟随、AR 标签跟随、循线。 |
| `kcf_track` | KCF 单目标视觉跟踪与目标跟随。 |
| `darknet_ros`、`darknet_ros_msgs` | YOLO/Darknet 实时目标检测及检测框消息。 |
| `ros_tensorflow` | TensorFlow 1 风格分类与目标检测示例，版本较旧，Jetson 部署应谨慎处理依赖。 |
| `wheeltec_yolo_action` | 自定义视觉自主行驶：结合 YOLO、循线和激光检测，识别路口、施工、停靠等场景，并输出控制数据。 |
| `bodyreader` | Astra 人体骨架识别、人体跟随、姿态/动作交互、反馈与显示。 |

学习这些包前，先保证相机图像稳定可见，并明确谁拥有 `/cmd_vel` 的控制权。多个跟随/导航节点同时发布 `/cmd_vel` 会造成危险的控制冲突；应使用 `twist_mux` 或只启动一种控制模式。

### E. 语音、交互与多机器人层（拓展阶段）

| 包 | 用途 |
|---|---|
| `xf_mic_asr_offline_circle` | 科大讯飞离线唤醒、命令词识别、导航点控制、运动控制和语音反馈。 |
| `tts_make` | 文本转语音。 |
| `wheeltec_multi` | 主从车、TF/里程计传递、编队跟随、避障、多车导航。 |
| `world_canvas_msgs` | 地图、标注及其服务接口；工程中用于地图保存。 |
| `ddynamic_reconfigure` | 动态创建 ROS 参数的库，供运行中调参使用。 |

## 3. 推荐学习顺序

不要按目录顺序阅读。建议按下列七个阶段推进；前一阶段的检查失败时，不进入下一阶段。

### 阶段 0：ROS 网络与工作区

目标：电脑虚拟机能看到 Nano 上的 ROS 数据。

1. 虚拟机使用桥接网络，不使用 NAT；Nano 与虚拟机必须双向 `ping`。
2. 所有设备指向同一个 `ROS_MASTER_URI`；虚拟机使用自己的可达 `ROS_IP`。
3. 在虚拟机上确认：

```bash
rostopic list
rosnode list
```

验收：能列出 Nano 上运行的节点和话题。

### 阶段 1：底盘通信和安全控制

目标：弄清楚真实车是如何被控制的。

```bash
roslaunch turn_on_wheeltec_robot turn_on_wheeltec_robot.launch
rostopic echo /odom
rostopic echo /imu
rostopic echo /PowerVoltage
```

然后用低速度、短时间测试 `/cmd_vel`。学习点：坐标系、线速度/角速度单位、串口权限、里程计方向、急停和速度限幅。

验收：`/odom` 在推车或行驶时变化；IMU 有稳定输出；底盘对安全的速度命令有正确响应。

### 阶段 2：雷达、TF 和 RViz

目标：确认导航最重要的空间数据链路。

```bash
roslaunch turn_on_wheeltec_robot wheeltec_lidar.launch
rostopic echo /scan
rosrun tf view_frames
```

在 RViz 中添加 `LaserScan`、`RobotModel` 和 `TF`。重点检查激光雷达方向、`laser` 到 `base_footprint` 的静态变换、车体遮挡角度和量程。

验收：RViz 中雷达点云位置与现实障碍物一致，TF 树没有断裂。

### 阶段 3：手动建图

目标：理解 SLAM 输入输出，不急于导航。

```bash
roslaunch turn_on_wheeltec_robot mapping.launch mapping_mode:=gmapping
```

用遥控让车缓慢绕场地走一圈，在 RViz 中观察 `/map`。地图闭环、墙体平直和漂移程度比“快速跑完整场地”更重要。

验收：能保存 `yaml + pgm` 地图，并知道地图文件、分辨率、原点和占据概率的含义。

### 阶段 4：固定地图定位和导航

目标：建立最稳定的自主导航闭环。

```bash
roslaunch turn_on_wheeltec_robot navigation.launch
```

在 RViz 中先使用“2D Pose Estimate”设置初始位姿，再使用“2D Nav Goal”发送目标点。

排障顺序：`/scan` → `/odom` → TF → `/map` → AMCL 位姿 → 全局路径 → 局部路径 → `/cmd_vel`。

验收：机器人能够绕开固定障碍物，到达目标附近，并在失败时触发合理恢复行为。

### 阶段 5：局部规划与参数调试

目标：能够解释“为什么不走、撞障碍、抖动或转圈”。

优先阅读：

- `params_costmap_common/`：机器人尺寸、传感器障碍物层、膨胀半径；
- `params_nav_common/teb_local_planner_params.yaml`：速度、加速度、目标容差和避障参数；
- 各底盘类型对应的 `params_costmap_car/param_*`：运动学模型与车体尺寸。

一次只改一个参数，并记录“场景—参数—现象—结果”。

### 阶段 6：相机与视觉行为

目标：从“看到图像”逐步走到“感知影响行为”。

顺序建议：`usb_cam/astra_camera` → 图像查看 → `simple_follower` → `darknet_ros` → `wheeltec_yolo_action`。

先只订阅和显示图像/检测框；确认识别稳定后，再允许行为节点发布控制命令。

### 阶段 7：语音、人体交互与多车

目标：在稳定导航基础上扩展交互能力。

建议顺序：离线语音命令识别 → 固定点导航调用 → 人体跟随 → 多机器人命名空间、TF 与通信隔离。

## 4. 每个包的标准学习方法

面对一个新功能包，按同一套问题理解它：

1. **它解决什么问题？** 阅读 `README.md`、`package.xml` 的 description 和 `launch/` 目录。
2. **它如何启动？** 找到 `*.launch`，列出 `<arg>`、`<param>`、`<remap>`、`<include>` 和 `<node>`。
3. **它依赖什么输入？** 使用：

```bash
rosnode info /节点名
rostopic info /话题名
rqt_graph
```

4. **它输出什么？** 记录发布话题、服务、Action、TF 和参数；特别确认是否会发布 `/cmd_vel`。
5. **核心逻辑在哪里？** C++ 优先看 `src/*.cpp` 中的订阅回调和 `advertise`；Python 优先看 `scripts/*.py` 中的 `Publisher`、`Subscriber` 和主循环。
6. **如何独立验证？** 先用 `rostopic echo`、RViz、rqt_plot 或 bag 文件验证输入输出，再整合到整车启动文件。
7. **如何恢复？** 明确停止命令、速度归零方式、设备占用的串口/USB，以及失败日志所在位置。

## 7. 当前阶段的建议

当前应先完成“阶段 0 到阶段 3”：修复虚拟机桥接 ROS 网络、读取 Nano 的 `/odom` `/imu` `/scan`、在 RViz 验证 TF，再以 `gmapping` 手动建图。地图质量稳定以后再进入 AMCL 和导航，不建议一开始就运行 YOLO、语音、人体跟随或多车功能。
