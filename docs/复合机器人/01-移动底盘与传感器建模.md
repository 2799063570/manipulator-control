# 移动底盘与传感器建模

> 本文是 [[移动操作臂Gazebo仿真实施方案]] 的“阶段 1”详细实施手册。完成本文全部检查后，再进入机械臂与底盘集成阶段。

## 1. 阶段目标与边界

本阶段只解决“机器人模型和传感器数据是否可信”的问题，不接入 SLAM、Nav2、MoveIt2 或任务状态机。阶段结束时，机器人应能在 RViz 和 Gazebo 中正确显示；轮子、传感器和机械臂安装位姿正确；激光与 IMU 话题可稳定输出。

#### 1.1 本阶段交付物与完成定义

完成本阶段后，代码目录至少应包含：

```text
mobile_manipulator_description/
├─ urdf/
│  ├─ materials.xacro
│  ├─ mobile_base.xacro
│  ├─ sensors.xacro
│  ├─ aubo_mount.xacro
│  └─ mobile_manipulator.urdf.xacro
├─ meshes/
└─ launch/display.launch.py

mobile_manipulator_gazebo/
├─ worlds/empty_lab.sdf
└─ launch/model_test.launch.py
```

本阶段完成定义：

- Xacro 能展开为合法 URDF；
- RViz 中可显示底盘、传感器安装位和 AUBO i5；
- Gazebo 中模型会受重力影响，车轮能与地面正常接触；
- `/scan_front`、`/scan_rear`（若采用双雷达）和 `/imu/data` 持续输出；
- 所有传感器数据都有可查询的 TF；
- 收纳姿态下可量化激光遮挡范围，而不是凭视觉猜测。

#### 1.2 先固定坐标系和命名规范

必须先确定坐标系，之后不能在不同功能包中随意更名。遵循 REP-103：x 向前、y 向左、z 向上；角度单位为 rad，长度单位为 m。

```text
base_footprint    地面投影点；z=0，作为移动底盘的平面参考
  └─ base_link    底盘刚体中心；用于安装机械臂和传感器
      ├─ wheel_fl_link / wheel_fr_link / wheel_rl_link / wheel_rr_link
      ├─ lidar_front_link
      ├─ lidar_rear_link
      ├─ imu_link
      └─ arm_base_link
```

`base_footprint → base_link` 应为固定关节。`base_link` 原点建议放在底盘几何中心附近、底盘上表面以下，便于表达重心和机械臂安装位姿。不要把原点放在某个轮子或底盘角落，否则轮距、碰撞边界和导航 footprint 的计算会变得混乱。

#### 1.3 先用参数化 Xacro 描述底盘

将尺寸放在 Xacro 属性中，避免在多个文件中写死同一个数值。下例是推荐的起点，不是最终机械设计值：

```xml
<!-- mobile_base.xacro -->
<xacro:property name="base_length" value="1.00"/>
<xacro:property name="base_width"  value="0.72"/>
<xacro:property name="base_height" value="0.16"/>
<xacro:property name="wheel_radius" value="0.10"/>
<xacro:property name="wheel_width"  value="0.05"/>
<xacro:property name="wheelbase"     value="0.72"/>
<xacro:property name="track_width"   value="0.60"/>

<link name="base_footprint"/>
<joint name="base_footprint_joint" type="fixed">
  <parent link="base_footprint"/>
  <child link="base_link"/>
  <origin xyz="0 0 ${wheel_radius}" rpy="0 0 0"/>
</joint>

<link name="base_link">
  <visual>
    <origin xyz="0 0 ${base_height / 2}"/>
    <geometry><box size="${base_length} ${base_width} ${base_height}"/></geometry>
  </visual>
  <collision>
    <origin xyz="0 0 ${base_height / 2}"/>
    <geometry><box size="${base_length} ${base_width} ${base_height}"/></geometry>
  </collision>
  <!-- 质量和惯量必须由 CAD 或近似长方体计算后填写，不能长期使用 1 或 0。 -->
  <inertial>
    <origin xyz="0 0 ${base_height / 2}"/>
    <mass value="80.0"/>
    <inertia ixx="4.0" ixy="0" ixz="0" iyy="7.0" iyz="0" izz="10.0"/>
  </inertial>
</link>
```

说明：示例中的质量和惯量只用于让 Gazebo 初步稳定运行，最终值必须依据底盘、电池、驱动器、AUBO i5、末端工具和负载重新计算。视觉模型可以使用复杂 mesh；碰撞模型应优先使用 box、cylinder 等简化几何体，以保证仿真稳定和 MoveIt2 碰撞检测速度。

#### 1.4 建立四个车轮与接触模型

四轮差速底盘使用左前、左后、右前、右后四个连续旋转关节。每个轮子应满足：

1. 轮轴沿机器人 y 轴；轮子旋转关节轴写为 `axis xyz="0 1 0"`。
2. 左右轮的转动方向在控制器中统一处理，不能依靠复制后随意翻转 mesh 解决。
3. 轮子 collision 建议用 cylinder，视觉 mesh 可以更精细。
4. 左右两侧的前后轮距离为 `wheelbase`，左右距离为 `track_width`。
5. 若真机是四轮独立驱动，仿真仍可将左右两轮交给同一个 `diff_drive_controller`；阶段 3 再配置控制器。

单轮 Xacro 宏示例：

```xml
<xacro:macro name="wheel" params="name x y">
  <link name="${name}_link">
    <visual>
      <origin rpy="1.5707963 0 0"/>
      <geometry><cylinder radius="${wheel_radius}" length="${wheel_width}"/></geometry>
    </visual>
    <collision>
      <origin rpy="1.5707963 0 0"/>
      <geometry><cylinder radius="${wheel_radius}" length="${wheel_width}"/></geometry>
    </collision>
  </link>
  <joint name="${name}_joint" type="continuous">
    <parent link="base_link"/>
    <child link="${name}_link"/>
    <origin xyz="${x} ${y} 0"/>
    <axis xyz="0 1 0"/>
  </joint>
</xacro:macro>

<xacro:wheel name="wheel_fl" x="${wheelbase / 2}"  y="${track_width / 2}"/>
<xacro:wheel name="wheel_fr" x="${wheelbase / 2}"  y="${-track_width / 2}"/>
<xacro:wheel name="wheel_rl" x="${-wheelbase / 2}" y="${track_width / 2}"/>
<xacro:wheel name="wheel_rr" x="${-wheelbase / 2}" y="${-track_width / 2}"/>
```

完成后先在空 Gazebo 世界测试：模型落地后车轮应接触地面，底盘不应沉入地面、弹跳或侧翻。若出现抖动，优先检查惯量、轮子 collision 重叠、地面摩擦和关节阻尼，而不是立即提高控制器增益。

#### 1.5 机械臂安装位与遮挡分析

将 AUBO i5 安装到 `arm_base_link` 时，应使用固定关节，安装位姿来自 CAD 或实际测量：

```xml
<joint name="arm_mount_joint" type="fixed">
  <parent link="base_link"/>
  <child link="arm_base_link"/>
  <origin xyz="-0.08 0 0.18" rpy="0 0 0"/>
</joint>
```

上例中的数字仅为占位示意。安装位置应同时满足：收纳姿态不越过底盘外廓太多、前伸时不易倾覆、底座不遮挡主要雷达、维护空间足够。

激光遮挡应以“**收纳姿态和典型抓取姿态下，传感器扫描平面是否与机械臂/立柱 collision 相交**”判断。Gazebo 中可以打开激光可视化，并在 RViz 中查看 `LaserScan` 缺失的角度区间。记录被遮挡的扇区角度、距离和姿态；这份记录将决定采用单雷达还是双雷达。

#### 1.6 是否采用双雷达：推荐决策

机械臂放在车上确实可能遮挡 2D 激光的部分方向，尤其是雷达与机械臂底座处在同一高度时。但双雷达不是无条件必选项，应按下表决策：

| 情况 | 建议 |
| --- | --- |
| 收纳姿态下单个 360° 雷达仅有很小遮挡，且遮挡不朝向行驶方向 | 单雷达即可 |
| 收纳姿态下机械臂/立柱遮挡前方或后方大扇区 | 使用前后双雷达 |
| 机器人需要频繁倒车、在狭窄工位转向 | 使用前后双雷达 |
| 机械臂会在移动中运动 | 不建议一期实现；若必须实现，双雷达或 3D 雷达是前提 |
| 既要高质量建图又要对机械臂姿态变化鲁棒 | 主 2D 雷达 + 第二避障雷达；后续升级 3D 雷达 |

**本项目推荐配置：前后双 2D 雷达。** 前雷达作为建图主传感器，前后雷达共同服务 Nav2 局部避障。这样既解决机械臂遮挡，也避免一开始就把双雷达融合、SLAM 和控制问题耦合在一起。

推荐安装方式：

```text
俯视图（x 向前）

      lidar_front_link
             ↓
     ┌─────────────────┐
     │     前保险杠     │
     │                 │
     │      AUBO i5    │
     │                 │
     │     后部电池     │
     └─────────────────┘
             ↑
       lidar_rear_link
```

- 前后雷达分别放在机械臂底座前方和后方，离底盘边缘保留保护距离；
- 两颗雷达的扫描平面高度相同或接近，避免一个扫到台面、另一个扫到地面；
- 两者视场角至少保留 60–90° 重叠区；
- 雷达支架、线束和防撞条也应加入 collision 模型；
- 若 360° 雷达成本允许，前后各一颗 360° 雷达最简单；若使用 270° 雷达，则前雷达朝前、后雷达朝后。

#### 1.7 双雷达的数据使用原则

`slam_toolbox` 的标准输入是一个 `sensor_msgs/LaserScan`。两颗物理位置不同的雷达不能简单将数组拼接成同一帧数据，否则会把不同观测原点错误地当成同一个原点，导致地图重影。

一期按以下原则实现：

```text
/scan_front ─────────────→ slam_toolbox（主建图雷达）
       │
       └─────────────────→ Nav2 local costmap obstacle layer

/scan_rear ──────────────→ Nav2 local costmap obstacle layer
```

Nav2 可以将前、后两个扫描话题分别配置为两个 obstacle source。示意配置：

```yaml
local_costmap:
  local_costmap:
    ros__parameters:
      observation_sources: scan_front scan_rear
      scan_front:
        topic: /scan_front
        data_type: LaserScan
        marking: true
        clearing: true
        obstacle_max_range: 4.0
      scan_rear:
        topic: /scan_rear
        data_type: LaserScan
        marking: true
        clearing: true
        obstacle_max_range: 3.0
```

二期若需要使用两颗雷达共同建图，应使用经过 TF 变换的激光融合节点，将各束激光投影到同一虚拟扫描平面后再输出一个 `LaserScan`；必须通过建图重影、墙面残差和重复路径测试验证融合质量。若两颗雷达间距很大，或机械臂动态遮挡频繁，升级 3D LiDAR / 点云建图通常比强行合并两个 2D `LaserScan` 更可靠。

#### 1.8 传感器 Xacro 示例

将传感器定义为可复用宏。下面示例展示 Gazebo Sim 的 2D 雷达定义；`topic` 应使用两个不同名称：

```xml
<!-- sensors.xacro -->
<xacro:macro name="gpu_lidar" params="link_name topic">
  <gazebo reference="${link_name}">
    <sensor name="${link_name}_sensor" type="gpu_lidar">
      <always_on>1</always_on>
      <visualize>true</visualize>
      <update_rate>12</update_rate>
      <topic>${topic}</topic>
      <gz_frame_id>${link_name}</gz_frame_id>
      <lidar>
        <scan>
          <horizontal>
            <samples>720</samples>
            <resolution>1</resolution>
            <min_angle>-3.1415926</min_angle>
            <max_angle>3.1415926</max_angle>
          </horizontal>
        </scan>
        <range>
          <min>0.10</min>
          <max>15.0</max>
          <resolution>0.01</resolution>
        </range>
      </lidar>
    </sensor>
  </gazebo>
</xacro:macro>
```

传感器安装位例子：

```xml
<link name="lidar_front_link"/>
<joint name="lidar_front_joint" type="fixed">
  <parent link="base_link"/>
  <child link="lidar_front_link"/>
  <origin xyz="0.38 0 0.38" rpy="0 0 0"/>
</joint>
<xacro:gpu_lidar link_name="lidar_front_link" topic="/scan_front"/>

<link name="lidar_rear_link"/>
<joint name="lidar_rear_joint" type="fixed">
  <parent link="base_link"/>
  <child link="lidar_rear_link"/>
  <origin xyz="-0.38 0 0.38" rpy="0 0 3.1415926"/>
</joint>
<xacro:gpu_lidar link_name="lidar_rear_link" topic="/scan_rear"/>
```

安装位数值需按照实际底盘外廓和 AUBO i5 收纳姿态调整。后雷达绕 z 轴旋转 π，是为了使其前向与机器人后方一致；若使用 360° 雷达，这个旋转不影响覆盖范围，但保留统一的“传感器前向”约定仍有助于调试。

IMU 推荐安装在接近整机质心的刚性位置。它不应安装在机械臂连杆、软支架或会发生相对振动的位置。IMU 的 `imu_link` 需要通过固定关节连接至 `base_link`，并在 Gazebo 中发布角速度、线加速度和姿态。

#### 1.9 Gazebo 与 ROS 2 桥接

Gazebo Sim 传感器话题需通过 `ros_gz_bridge` 转成 ROS 2 消息。双雷达和 IMU 的桥接参数示例：

```python
sensor_bridge = Node(
    package='ros_gz_bridge',
    executable='parameter_bridge',
    arguments=[
        '/scan_front@sensor_msgs/msg/LaserScan[gz.msgs.LaserScan',
        '/scan_rear@sensor_msgs/msg/LaserScan[gz.msgs.LaserScan',
        '/imu/data@sensor_msgs/msg/Imu[gz.msgs.IMU',
    ],
    output='screen',
)
```

不同 Gazebo / `ros_gz_bridge` 小版本可能对 IMU 的 Gazebo 消息名称或话题名有差异。先在 Gazebo 中使用 `gz topic -l` 确认实际话题，再写入 bridge 参数；不要假定每个世界都叫 `/imu/data`。

#### 1.10 本阶段逐项验证

按以下顺序验证，任一步失败都先修复再进入下一步：

1. 展开模型：`xacro mobile_manipulator.urdf.xacro > /tmp/mobile_manipulator.urdf`。
2. 检查 URDF：`check_urdf /tmp/mobile_manipulator.urdf`。
3. 在 RViz 中验证每个 link、joint 和传感器坐标系。
4. 在空 Gazebo 世界生成机器人，观察 30 秒，确认不会弹跳、下沉或倾倒。
5. 打开 Gazebo 激光可视化，分别观察收纳姿态和典型抓取姿态下的前、后雷达遮挡区域。
6. 验证 ROS 话题：

```bash
ros2 topic hz /scan_front
ros2 topic hz /scan_rear
ros2 topic hz /imu/data
ros2 run tf2_ros tf2_echo base_link lidar_front_link
ros2 run tf2_ros tf2_echo base_link lidar_rear_link
ros2 run tf2_ros tf2_echo base_link imu_link
```

7. 在 RViz 中添加两个 `LaserScan` 显示项，分别指定 `/scan_front` 与 `/scan_rear`，确认扫描原点与障碍物位置一致。
8. 保存“雷达遮挡测试”截图与参数表，作为进入阶段 2 的基线资料。

验收标准：Xacro 和 URDF 检查通过；Gazebo 模型稳定；每个传感器都有有效 TF；前后扫描均稳定输出；收纳姿态下前方、后方行驶方向不存在无法接受的盲区。
