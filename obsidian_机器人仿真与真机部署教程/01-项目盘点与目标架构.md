# 项目盘点与目标架构

## 1. 已有控制链路

当前代码已实现一个很好的“控制算法原型”：`RobotState` 保存 q/dq，`SafetyLimiter` 对位置/速度限幅，`CubicInterpolator` 产生三次/五次轨迹，`TrajectoryBuffer` 在控制周期逐点取出轨迹，`JacobianSolver` 用伪逆或阻尼最小二乘（DLS）求关节速度。

`vel_to_pos_node.cpp` 已把这条思路落成 ROS 2 节点：

```text
/joint_velocity_cmd
  -> Vel2PosNode（限幅 + 五次插值 + 缓冲）
  -> /joint_position_cmd
  -> joint_position_cmd_to_states
  -> /joint_states -> robot_state_publisher -> TF -> RViz
```

这是**教学闭环**，不等价于工业级实时控制。原因是它没有读取真实反馈、没有时间戳对齐、没有标准 action、没有故障状态机。后续保留算法库，但将最终执行接口替换成 `joint_trajectory_controller` 或厂商驱动。

## 2. 两套应该并存的接口

| 层级 | 教学/快速验证 | 工程部署推荐 |
|---|---|---|
| 关节命令 | 自定义 `JointPositionCmd` / `JointVelocityCmd` | `control_msgs/action/FollowJointTrajectory` |
| 控制器 | `joint_position_cmd_to_states` | `joint_trajectory_controller`、`diff_drive_controller` |
| 状态 | 手动发布 `/joint_states` | 硬件接口/状态广播器发布 |
| 仿真后端 | 仅 RViz | Gazebo Sim + `gz_ros2_control` |
| 硬件后端 | 不适用 | `ros2_control` SystemInterface 或厂商 ROS 2 driver |

## 3. 目标分层

```text
任务层：抓取任务、巡航任务、行为树
规划层：MoveIt 2（机械臂）/ Nav2（移动底盘）
控制层：轨迹生成、限幅、PID、速度解算
执行层：ros2_control controller_manager
适配层：GazeboSimSystem / 真机 SystemInterface / 厂商驱动
硬件层：控制柜、伺服、编码器、MCU、雷达、相机
```

> [!warning] 当前代码的两个实现风险
> 1. `vel_to_pos_node.cpp` 中日志固定访问六个关节，`dof != 6` 时越界；应按 `dof_` 循环格式化，或限制节点只能用于六轴臂。
> 2. 轨迹缓冲区在连续速度命令到来时会累积旧轨迹；工程版本需在新命令到来时清队列，或使用时间戳与 preemption（抢占）策略。

## 4. 推荐里程碑

1. 二维臂：Gazebo 中接受 `FollowJointTrajectory`，MoveIt 计划并执行。
2. 二维臂：加入工作台、物体、夹爪，验证碰撞与抓放。
3. AUBO：复制二维臂的控制闭环，先 fake hardware，再 Gazebo，再厂商驱动。
4. 小车：完成 `cmd_vel -> 轮速 -> odom -> TF`，再接激光、SLAM、Nav2。
5. 真机：仅在急停、限速、零位、坐标系、反馈、通信丢失处理全部验收后上线。

## 5. ROS 图检查

每启动一个系统，保存一份证据：

```bash
ros2 node list
ros2 topic list -t
ros2 control list_controllers
ros2 run tf2_tools view_frames
rqt_graph
```

合格标准：控制器为 `active`；`/joint_states` 或 `/odom` 持续更新；TF 没有断链；命令、状态和模型的关节名完全一致。
