# 环境与工作区复现

## 1. 推荐版本

- OS：Ubuntu 24.04（Noble）。
- ROS：ROS 2 Jazzy。
- 仿真：Gazebo Harmonic（`gz sim`）。Jazzy 与 Harmonic 是推荐组合；本仓库的 `simple_arm_gazebo` 已使用 `ros_gz_sim`、`ros_gz_bridge`、`gz_ros2_control`，不是 Gazebo Classic。
- 规划：MoveIt 2 Jazzy。

小车的 `radius_simulator.xacro` 仍引用 `libgazebo_ros_laser.so`（Gazebo Classic 风格）。不要与 Gazebo Sim 插件混用；参见 [[05-移动机器人仿真与Nav2#4. 从 Gazebo Classic 迁移到 Gazebo Sim]]。

## 2. 安装依赖

```bash
sudo apt update
sudo apt install ros-jazzy-desktop ros-dev-tools \
  ros-jazzy-ros-gz ros-jazzy-gz-ros2-control \
  ros-jazzy-ros2-controllers ros-jazzy-joint-trajectory-controller \
  ros-jazzy-moveit ros-jazzy-moveit-servo \
  ros-jazzy-navigation2 ros-jazzy-nav2-bringup ros-jazzy-slam-toolbox \
  ros-jazzy-robot-localization ros-jazzy-twist-mux \
  ros-jazzy-rmw-cyclonedds-cpp \
  python3-colcon-common-extensions libeigen3-dev
```

> [!important] Jazzy/Harmonic 的版本边界
> 不要安装 `gazebo_ros_pkgs` 或沿用 Humble 的 Fortress/Classic 教程来满足本项目的 Gazebo Sim 依赖。Jazzy 推荐的组合是 Gazebo Harmonic；先安装聚合包 `ros-jazzy-ros-gz`，再安装 `ros-jazzy-gz-ros2-control`。若某个细分包在你的 apt 源中名称不同，以 `apt-cache search ros-jazzy | grep -E 'moveit|gz|nav2|slam|control'` 的输出为准；不要混装来自不同 Gazebo 大版本或第三方仓库的同名库。

安装完成后立即记录版本，之后排错时非常重要：

```bash
printenv ROS_DISTRO                 # 预期：jazzy
gz sim --versions                   # 预期：Harmonic / gz-sim8 系列
ros2 pkg prefix gz_ros2_control
ros2 pkg prefix moveit_ros_move_group
ros2 pkg prefix nav2_bringup
```

将以下内容加到 `~/.bashrc`：

```bash
source /opt/ros/jazzy/setup.bash
export ROS_DOMAIN_ID=20       # 同一局域网内与其他机器人隔离；所有协同设备需一致
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
```

如果没有特意安装 Cyclone DDS，可删除最后一行并使用 Jazzy 默认的 Fast DDS；中间件必须在同一 ROS 图中的机器上按测试结果统一，切勿一部分进程设置、一部分不设置。

## 3. 构建工作区

仓库包含多个相互独立的工作区。不要在仓库根目录盲目 `colcon build`；分别进入对应目录。

```bash
# 控制库、二维臂、MoveIt、Gazebo
cd ~/manipulator-control/robot_control_ros2
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash

# AUBO 描述包（当前主要是模型）
cd ~/manipulator-control/aubo_i5_ros2_control
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash
```

> [!tip] 为什么使用 `--symlink-install`
> 对 Python launch、YAML、URDF/Xacro 的编辑会立即反映到 install 空间，减少反复编译；C++ 源码改动仍必须重新 `colcon build`。

## 4. 先复现已有二维臂

```bash
cd ~/manipulator-control/robot_control_ros2
source /opt/ros/jazzy/setup.bash
source install/setup.bash

# Gazebo、控制器、MoveIt、RViz 一次启动
ros2 launch simple_arm_gazebo demo_gazebo.launch.py
```

另开终端检查：

```bash
source /opt/ros/jazzy/setup.bash
source ~/manipulator-control/robot_control_ros2/install/setup.bash
ros2 control list_controllers
ros2 topic echo /joint_states --once
ros2 action list -t
```

应看到 `joint_state_broadcaster` 与 `arm_controller` 处于 `active`，后者通常暴露 `FollowJointTrajectory` action。若 Gazebo 黑屏或渲染错误，尝试：

```bash
LIBGL_ALWAYS_SOFTWARE=1 ros2 launch simple_arm_gazebo demo_gazebo.launch.py
```

### Ubuntu 24.04 Wayland 下 RViz / MoveIt Setup Assistant 无法创建窗口

若启动 `moveit_setup_assistant`、RViz 或 MoveIt demo 时反复出现：

```text
rviz::RenderSystem: error creating render window
RenderingAPIException: Invalid parentWindowHandle (wrong server or screen)
Unable to create the rendering window after 100 tries
```

这是 Wayland 与 RViz 的 OGRE/GLX 图形后端兼容问题，不是 URDF、MoveIt 配置或 controller 错误。先用 X11 兼容模式启动：

```bash
source /opt/ros/jazzy/setup.bash
QT_QPA_PLATFORM=xcb ros2 run moveit_setup_assistant moveit_setup_assistant
```

仍失败时增加软件渲染：

```bash
QT_QPA_PLATFORM=xcb LIBGL_ALWAYS_SOFTWARE=1 \
  ros2 run moveit_setup_assistant moveit_setup_assistant
```

确认当前会话：

```bash
echo $XDG_SESSION_TYPE    # wayland / x11
echo $DISPLAY
```

长期稳定方案是在 Ubuntu 登录界面选择 **Ubuntu on Xorg** 后再运行 RViz/MoveIt。若在 SSH、Docker、WSL 或远程桌面中运行，还需单独确认 X11/图形转发是否可用。

## 5. 最小执行验证

先确认 action 名：`ros2 action list -t`。常见名称为 `/arm_controller/follow_joint_trajectory`：

```bash
ros2 action send_goal /arm_controller/follow_joint_trajectory \
  control_msgs/action/FollowJointTrajectory \
  "{trajectory: {joint_names: [joint1, joint2], points: [
    {positions: [0.5, -0.4], time_from_start: {sec: 2}}
  ]}}"
```

只在空场景、低速度、关节未接近限位时运行。若失败，先比对 `ros2 topic echo /joint_states --once` 的 `name` 与 YAML 的 `joints`。
