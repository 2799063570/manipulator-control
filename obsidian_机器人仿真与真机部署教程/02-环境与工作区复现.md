# 环境与工作区复现

## 1. 推荐版本

- OS：Ubuntu 22.04。
- ROS：ROS 2 Humble。
- 仿真：Gazebo Sim（`gz sim`），本仓库的 `simple_arm_gazebo` 已使用 `ros_gz_sim`、`ros_gz_bridge`、`gz_ros2_control`，不是 Gazebo Classic。
- 规划：MoveIt 2 Humble。

小车的 `radius_simulator.xacro` 仍引用 `libgazebo_ros_laser.so`（Gazebo Classic 风格）。不要与 Gazebo Sim 插件混用；参见 [[05-移动机器人仿真与Nav2#4. 从 Gazebo Classic 迁移到 Gazebo Sim]]。

## 2. 安装依赖

```bash
sudo apt update
sudo apt install ros-humble-desktop ros-humble-xacro \
  ros-humble-ros-gz-sim ros-humble-ros-gz-bridge ros-humble-gz-ros2-control \
  ros-humble-ros2-controllers ros-humble-joint-trajectory-controller \
  ros-humble-moveit ros-humble-moveit-servo \
  ros-humble-navigation2 ros-humble-nav2-bringup ros-humble-slam-toolbox \
  ros-humble-robot-localization ros-humble-twist-mux \
  python3-colcon-common-extensions libeigen3-dev
```

将以下内容加到 `~/.bashrc`：

```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=20       # 同一局域网内与其他机器人隔离；所有协同设备需一致
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
```

## 3. 构建工作区

仓库包含多个相互独立的工作区。不要在仓库根目录盲目 `colcon build`；分别进入对应目录。

```bash
# 控制库、二维臂、MoveIt、Gazebo
cd ~/manipulator-control/robot_control_ros2
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash

# AUBO 描述包（当前主要是模型）
cd ~/manipulator-control/aubo_i5_ros2_control
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash
```

> [!tip] 为什么使用 `--symlink-install`
> 对 Python launch、YAML、URDF/Xacro 的编辑会立即反映到 install 空间，减少反复编译；C++ 源码改动仍必须重新 `colcon build`。

## 4. 先复现已有二维臂

```bash
cd ~/manipulator-control/robot_control_ros2
source /opt/ros/humble/setup.bash
source install/setup.bash

# Gazebo、控制器、MoveIt、RViz 一次启动
ros2 launch simple_arm_gazebo demo_gazebo.launch.py
```

另开终端检查：

```bash
source /opt/ros/humble/setup.bash
source ~/manipulator-control/robot_control_ros2/install/setup.bash
ros2 control list_controllers
ros2 topic echo /joint_states --once
ros2 action list -t
```

应看到 `joint_state_broadcaster` 与 `arm_controller` 处于 `active`，后者通常暴露 `FollowJointTrajectory` action。若 Gazebo 黑屏或渲染错误，尝试：

```bash
LIBGL_ALWAYS_SOFTWARE=1 ros2 launch simple_arm_gazebo demo_gazebo.launch.py
```

## 5. 最小执行验证

先确认 action 名：`ros2 action list -t`。常见名称为 `/arm_controller/follow_joint_trajectory`：

```bash
ros2 action send_goal /arm_controller/follow_joint_trajectory \
  control_msgs/action/FollowJointTrajectory \
  "{trajectory: {joint_names: [joint1, joint2], points: [
    {positions: [0.5, -0.4], time_from_start: {sec: 2}}
  ]}}"
```

只在空场景、低速度、关节未接近限位时运行。若失败，先比对 `ros2 topic echo /joint_states --once` 的 `name` 与 YAML 的 `joints`。
