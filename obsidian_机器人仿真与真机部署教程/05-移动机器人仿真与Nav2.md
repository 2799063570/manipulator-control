# 移动机器人仿真与 Nav2

## 1. 当前底盘模型

`robot_move_control/src/fishbot_description` 提供 `base_link.xacro`、车轮、相机、雷达和组合文件 `assemble.xacro`。`radius_simulator.xacro` 已定义 360 线数、约 5.5 Hz 的二维 ray 激光，并发布 `/scan`；但插件 `libgazebo_ros_laser.so` 属于 Gazebo Classic。

目标闭环：

```text
/cmd_vel -> diff_drive_controller -> 左右轮接口 -> Gazebo/MCU
Gazebo/编码器 -> /odom + /joint_states -> robot_localization -> odom->base_link
雷达 -> /scan -> slam_toolbox / AMCL
map->odom + odom->base_link + base_link->laser -> Nav2
```

## 2. 建模约定（先统一再写代码）

- ROS 采用 REP-103：x 前、y 左、z 上；绕 z 轴逆时针为正。
- `base_link` 是机器人刚体坐标；`base_footprint` 投影在地面，常作为导航底盘坐标。
- `odom` 连续但会漂移；`map` 全局但可能在定位修正时跳变。`map -> odom` 来自 SLAM/AMCL，`odom -> base_link` 来自里程计融合。
- 激光 frame 应为 `laser` 或 `laser_frame`，使用静态 TF 与 `base_link` 连接；不要让两个节点同时发布同一 TF。

## 3. Gazebo Sim 的差速实现

建议新建 `fishbot_gazebo` 包，复用 description 包而非复制模型。为左右驱动轮加入 `ros2_control` 接口和 `gz_ros2_control` 插件；控制器 YAML 使用：

```yaml
controller_manager:
  ros__parameters:
    update_rate: 100
    joint_state_broadcaster:
      type: joint_state_broadcaster/JointStateBroadcaster
    base_controller:
      type: diff_drive_controller/DiffDriveController
base_controller:
  ros__parameters:
    left_wheel_names: [left_wheel_joint]
    right_wheel_names: [right_wheel_joint]
    wheel_separation: 0.32       # 用实测轮中心距替换
    wheel_radius: 0.05           # 用实测有效半径替换
    publish_rate: 50.0
    base_frame_id: base_footprint
    odom_frame_id: odom
    enable_odom_tf: false        # 交给 robot_localization 时关闭
```

轮名、轮距、半径均不能照抄；从 Xacro 与实物测量得到。若前进命令使机器人后退，优先检查关节轴向与左右轮速度符号，而不是在 Nav2 中“补偿”。

## 4. 从 Gazebo Classic 迁移到 Gazebo Sim

删除 Classic 的 `<plugin filename="libgazebo_ros_laser.so">` 依赖，改用 Gazebo Sim 的传感器 SDF 插件，并通过 `ros_gz_bridge` 桥接：

```bash
ros2 run ros_gz_bridge parameter_bridge \
  /scan@sensor_msgs/msg/LaserScan[gz.msgs.LaserScan
```

具体 Gazebo 传感器插件名称会随发行版变化；以本机 `gz plugin --list` 和 ROS 发行版文档为准。先在 Gazebo 内确认传感器 topic，再接桥接器，最后检查 ROS 中的 `/scan` 的 `header.frame_id`、角度、量程和频率。

## 5. SLAM 与 Nav2 启动顺序

1. 启动 Gazebo、robot_state_publisher、轮控制器、激光桥接。
2. 遥操作发布低速 `/cmd_vel`，确认直行与原地旋转，记录 `/odom`。
3. 启动 `robot_localization`（编码器 odom + IMU），确认只发布一条 `odom -> base_link`。
4. 启动 `slam_toolbox` 建图，手动慢速完整绕场一圈，保存 map。
5. 使用保存的 map 启动 AMCL + Nav2；在 RViz 设置 initial pose，再给 Navigation Goal。

Nav2 的速度应经过 `twist_mux`：遥操作、导航、急停三类来源按优先级仲裁，急停优先级最高且超时最短。

## 6. 调参的正确顺序

先传感器外参和时间戳，再轮径/轮距，再 EKF 协方差，再局部代价地图，再控制器，最后全局规划器。一个实用的轮径校准：让机器人直行测量实际距离 `d_real` 与 odom 距离 `d_odom`，更新 `r_new = r_old * d_real / d_odom`。原地旋转角度不准通常校正轮距。
