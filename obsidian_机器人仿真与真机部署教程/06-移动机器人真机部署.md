# 移动机器人真机部署

## 1. 推荐硬件与软件边界

| 模块 | 低层 MCU（实时） | 工控机/主机（ROS 2） |
|---|---|---|
| 电机控制 | PWM/FOC、编码器计数、过流保护、PID | 发送目标轮速 |
| 传感器 | 读取编码器、IMU 原始数据 | 雷达、相机、融合、建图导航 |
| 安全 | 硬件急停切断电机使能、看门狗 | 速度限幅、碰撞检测、任务状态机 |
| 通信 | 串口/CAN 帧解析 | `ros2_control` 硬件接口/串口节点 |

Linux 不是硬实时系统；电机电流环、速度环必须在驱动器/MCU 内闭环。ROS 2 负责较慢的轮速设定、状态估计与任务规划。

## 2. 最小硬件接口

为 `ros2_control` 实现左右轮 velocity command 与 position/velocity state interface。`read()` 从 MCU 取编码器累计角度和轮速；`write()` 将控制器输出的 rad/s 转成协议要求的 RPM/PWM。

换算：

\[
v = r\omega,\quad \omega_{L,R}=\frac{v \mp \frac{L}{2}\omega_z}{r},\quad RPM=\omega\frac{60}{2\pi}
\]

其中 `r` 为有效轮半径，`L` 为左右轮中心距。一定要在接口层处理轮子方向符号并做速度/加速度限幅；禁止把原始 `/cmd_vel` 直接变成 PWM。

## 3. 里程计与融合

纯轮速积分会随打滑漂移：

\[
x_{k+1}=x_k+v\cos\theta\Delta t,\quad y_{k+1}=y_k+v\sin\theta\Delta t,\quad \theta_{k+1}=\theta_k+\omega\Delta t
\]

使用 `robot_localization` 的 EKF 融合轮里程计和 IMU。输入协方差必须反映真实可信度：轮子打滑时提高 odom 协方差；低质量磁力计不应强行融合 yaw。不要同时让 diff_drive_controller、EKF、SLAM 发布同一 `odom->base_link`。

## 4. 真机 bringup 检查表

- 电池电压、保险、急停和电机使能在物理层逐一验证。
- 悬空测试左右轮：正 `cmd_vel.linear.x` 必须使两轮向前；正 `angular.z` 必须左轮后、右轮前（按坐标约定）。
- 读取连续 10 分钟编码器，确认没有跳变、溢出、丢帧。
- 雷达固定牢靠，`/scan` 的 `frame_id` 正确；相机内参/外参有可追溯标定文件。
- 通信断开时 MCU 在限定时间内将目标速度归零；ROS 节点重启不能导致电机突跳。
- 室内首次导航速度建议 ≤ 0.15 m/s，膨胀半径大于车体实际外接圆加安全余量。

## 5. 部署方式

开发机上构建后，可用 `rsync` 同步源码到机器人并在机器人本地构建，避免 ABI 差异：

```bash
rsync -av --exclude build --exclude install --exclude log \
  ~/manipulator-control/ robot@robot-pc:~/manipulator-control/
```

正式运行使用 systemd 或 Docker Compose 管理 bringup；日志写入持久目录，开机不应自动使能电机。将 `ROS_DOMAIN_ID`、网卡、设备串口路径用 udev 规则固定，避免 `/dev/ttyUSB0` 漂移。
