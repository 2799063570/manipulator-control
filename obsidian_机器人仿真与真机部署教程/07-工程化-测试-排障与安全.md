# 工程化、测试、排障与安全

## 1. 仿真到真机的质量门禁

| 门禁 | 必须通过的证据 |
|---|---|
| 模型 | `check_urdf` 通过；关节名/方向/限位一致；RViz TF 完整 |
| 控制 | controller 为 active；命令和状态单位一致；命令超时会停 |
| 仿真 | 低速轨迹稳定；模型有质量、惯量、碰撞；随机测试有记录 |
| 传感器 | frame、时间戳、频率、量程/内参可验证 |
| 真机 | 急停、软限位、通信超时、反馈异常均进入安全状态 |
| 应用 | 失败可取消、可恢复、有日志；不把安全寄托在 UI 操作 |

## 2. 高频排障表

| 症状 | 优先检查 | 常见原因 |
|---|---|---|
| 模型不动 | `ros2 control list_controllers` | controller 未 active、关节名不匹配、插件未加载 |
| MoveIt 只规划不执行 | action 名与 `moveit_controllers.yaml` | 控制器 action 配置错误、控制器未启动 |
| TF 报重复发布 | `view_frames`、节点列表 | 两个节点发布同一 parent-child，例如 odom->base_link |
| Gazebo 抖动/飞走 | inertia、collision、关节 limit | 零质量、惯量不合理、穿模、初始重叠 |
| 小车前进变后退 | wheel joint axis、轮名 | 坐标轴或左右方向反了 |
| Nav2 原地转/撞墙 | map/odom/laser TF、costmap | 里程计漂移、激光 frame 错、机器人 footprint 错 |
| 真机突然跳动 | 初值、使能顺序、单位 | 命令与反馈不一致、deg/rad 或 RPM/rad/s 混淆 |

## 3. 日志与可复现性

为每次实验记录 Git commit、ROS 版本、机器人参数版本、地图版本、bag 名称和验收结论。关键 topic 录包：

```bash
ros2 bag record /tf /tf_static /joint_states /scan /odom /cmd_vel \
  /diagnostics /controller_manager/robot_description
```

硬件运行时避免录制高带宽原始图像，除非磁盘与 CPU 已压测；关键是先保证控制不会被日志阻塞。

## 4. 安全设计原则

1. 硬件急停优先于软件急停。
2. 上层命令永远经过速度、加速度、位置与工作空间限制。
3. 新控制器在仿真、悬空、低速、空载、隔离区依次验证。
4. 通信/传感器/时钟异常默认停，不默认继续跑旧命令。
5. 安全功能要能独立测试，例如拔网线、停止雷达、发布超限命令。
