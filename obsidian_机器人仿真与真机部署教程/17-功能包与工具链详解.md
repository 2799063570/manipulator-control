# 功能包与工具链详解

## 1. 先理解 package 的层级

ROS 2 package 是构建、安装和运行的基本单元；一个 workspace 可含多个 package。`package.xml` 声明依赖和元信息，`CMakeLists.txt` 定义 C++ 构建、目标和安装规则。`colcon build` 只会构建当前 workspace 中的 package，`source install/setup.bash` 才会让 ROS 找到它们。

依赖类型：`buildtool_depend` 是 ament_cmake；`build_depend` 用于编译；`exec_depend` 用于运行；`depend` 等同常见 build+exec 依赖。修改 package.xml 后建议执行 `rosdep install --from-paths src --ignore-src -r -y`，不要手工猜 apt 包名。

## 3. 基础 ROS 2 包

### rclcpp

C++ 客户端库。`rclcpp::Node` 是节点基类；`create_publisher`、`create_subscription`、`create_wall_timer`、`declare_parameter` 是最常用 API。`rclcpp::spin(node)` 使用 executor 持续调度回调。复杂节点使用 `MultiThreadedExecutor` 前先确认共享状态有锁或无锁保护；控制循环不要因 callback 锁等待而阻塞。

### std_msgs、geometry_msgs、sensor_msgs、nav_msgs

`std_msgs` 只放简单数据；速度命令用 `geometry_msgs/Twist` 或带 frame/time 的 `TwistStamped`；传感器状态用 `sensor_msgs/JointState`、`Imu`、`LaserScan`、`Image`；里程计用 `nav_msgs/Odometry`。优先标准类型能直接接 RViz、Nav2、MoveIt 和 rosbag。

### tf2_ros 与 robot_state_publisher

`tf2_ros` 提供 TransformBroadcaster、StaticTransformBroadcaster、Buffer、TransformListener。静态变换只发布一次；动态变换要有准确 timestamp。`robot_state_publisher` 从 URDF 和 joint_states 自动发布机械结构 TF，切勿自己重复发布同一 link 对。

### xacro、urdf、joint_state_publisher_gui

URDF 是 XML 机器人树；Xacro 是生成 URDF 的宏语言，适合参数、include、条件分支。调试命令：`ros2 run xacro xacro model.xacro > /tmp/model.urdf`、`check_urdf /tmp/model.urdf`。`joint_state_publisher_gui` 只适合无控制器时手动拖动关节，不能作为仿真/真机状态源。

## 4. ros2_control 生态

### hardware_interface / controller_manager

`ros2_control` 把上层控制与硬件分开。硬件导出 command interfaces（position/velocity/effort）与 state interfaces；`controller_manager` 以 update_rate 周期调用硬件 read、controller update、硬件 write。真实硬件实现 `SystemInterface`；仿真使用 `gz_ros2_control`；测试用 `mock_components`。

### joint_state_broadcaster

读取 state interfaces，发布 `/joint_states` 与动态 joint state。它不执行任何命令，是模型状态可视化/MoveIt 监控的基础。

### joint_trajectory_controller

接收 `FollowJointTrajectory` action 或轨迹 topic，以严格时间点执行多关节轨迹，输出 position/velocity/effort 命令。它会检查 joint names、时间单调性、允许误差和 goal tolerance。机械臂最终应主要接这个 action，而非自定义 position topic。

### diff_drive_controller

订阅速度命令，按轮半径/轮距换算左右轮目标速度，利用反馈发布 odometry，可选发布 odom TF。输入必须经过限速与 timeout；轮名和轴方向错时，所有导航调参都无效。

### gz_ros2_control 与 ros_gz_bridge

`gz_ros2_control` 是 Gazebo Sim 的硬件后端，使同一个 controller YAML 可用于仿真；`ros_gz_bridge` 在 Gazebo 消息与 ROS 消息间桥接 `/clock`、LaserScan、Image 等。它们与 Gazebo Classic 的 `gazebo_ros2_control`、`libgazebo_ros_*` 不是同一插件体系，不能混配。

## 5. MoveIt 2 生态

| 包/组件 | 职责 | 你在项目中的用法 |
|---|---|---|
| `moveit_ros_move_group` | MoveIt 核心服务器 | 规划、碰撞、执行入口 |
| `moveit_configs_utils` | 从 config 构造参数 | 当前 launch 的 MoveItConfigsBuilder |
| `moveit_setup_assistant` | 生成初始配置 | 给 AUBO 创建 SRDF/配置骨架 |
| `moveit_planners_ompl` | 采样规划器 | RRTConnect、RRTstar、PRM 等 |
| `moveit_kinematics` | FK/IK 插件层 | 配置 KDL/TRAC-IK 等 |
| `moveit_servo` | 实时笛卡尔/关节 jog | 替代简化速度积分节点 |
| `moveit_ros_visualization` | RViz MotionPlanning | 调试规划和场景 |

`move_group` 接受 MotionPlanRequest：起始状态、目标、路径约束、规划组、规划时间。它输出轨迹后调用 controller action。它不是硬实时控制器，也不是硬件驱动。

## 6. 移动机器人生态

### robot_localization

提供 EKF/UKF。用轮里程计预测，再由 IMU、GPS、视觉等修正。输入 frame、时间戳和协方差必须可信；它不能修复错误轮径、错误 IMU 轴向或重复 TF。

### slam_toolbox 与 nav2_map_server

`slam_toolbox` 以 LaserScan、TF 和 odom 建二维图并发布 map-to-odom。`map_saver_cli` 保存 map yaml+图像。先建图、验图、保存，再进入定位导航；建图时不应同时让 AMCL 发布 map-to-odom。

### Nav2

Nav2 由 map server、AMCL、planner server、controller server、behavior server、BT Navigator 和 costmap 组成。全局 planner 产出路径，局部 controller 跟踪并避障，行为树编排恢复。它依赖完整 `map -> odom -> base_link -> laser` 和可靠 `/scan`、`/odom`。

### twist_mux、teleop_twist_keyboard、diagnostic_updater

`twist_mux` 按优先级与超时仲裁遥控、导航和急停速度；真机必须有。`teleop_twist_keyboard` 只用于低速测试。`diagnostic_updater` 将电压、通信、故障码统一发布给 `rqt_robot_monitor` 等工具。

## 7. 必备调试工具包

`rqt_graph` 看连接；`rqt_plot` 看误差/速度；`rqt_reconfigure`（ROS 2 情况有限）和 parameters 看参数；`tf2_tools view_frames` 看坐标树；`ros2 bag` 录制回放；`ros2 doctor` 诊断环境；`rviz2` 看模型、激光、地图和路径。调试顺序永远是：参数与节点 -> topic 类型/QoS -> 内容/频率 -> TF -> 应用行为。
