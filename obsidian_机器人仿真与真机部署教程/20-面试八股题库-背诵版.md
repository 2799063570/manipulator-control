# 面试八股题库：背诵版

> [!tip] 回答结构
> 先用一句话定义；再说机制或公式；最后连接项目中的实现和风险。不要只背名词，也不要把仿真能力夸成真机量产能力。

## ROS 2 与通信

### 1. ROS 2 的节点、topic、service、action 分别是什么？

**背诵答案：** 节点是执行计算的基本单元。Topic 是异步多对多数据流，适合传感器、状态和连续速度；Service 是短时请求响应，适合读取配置或触发一次操作；Action 适合耗时任务，提供 goal、feedback、result 和 cancel，例如机械臂轨迹和导航。项目中我用自定义 topic 学习关节命令，但执行层会使用 FollowJointTrajectory action，以支持反馈、取消和抢占。

**追问：为什么不用 Service 发轨迹？** Service 无持续 feedback、标准取消和抢占语义；轨迹执行时间长，Action 更匹配。

### 2. QoS 有哪些关键策略？

**背诵答案：** 关键是 reliability、durability、history/depth。Reliable 尽力确保送达，Best Effort 允许丢包以降低延迟；Transient Local 让后来订阅者收到最后一条，Volatile 不保留。传感器常 Best Effort，控制状态/关键事件常 Reliable。两端 QoS 不兼容会出现 topic 可见但没有数据，我用 `ros2 topic info -v` 排查。

### 3. ROS 2 是实时系统吗？

**背诵答案：** ROS 2 具备构建实时系统的基础，但默认 Linux、DDS、动态内存和普通 executor 不保证确定性。实时控制需实时内核、线程优先级、预分配内存、避免锁和阻塞 I/O。项目中把电机电流/速度内环放 MCU 或驱动器，ROS 2 负责较慢的规划、轮速目标和状态融合。

### 4. 解释参数、launch、namespace 和 remap。

**背诵答案：** 参数是运行期配置，适合速度限制和设备地址；launch 用于同时启动节点、传参、条件分支和事件编排；namespace 隔离多机器人名称；remap 在不改代码时改变接口名称。硬件 IP、标定值应由私密参数文件提供，不能硬编码在 description 包。

## TF、URDF、坐标系

### 5. map、odom、base_link 有何区别？

**背诵答案：** base_link 是机器人本体坐标；odom 局部连续，允许长期漂移；map 是全局一致坐标，允许定位校正跳变。常见分工是 EKF/轮里程计发布 odom 到 base_link，SLAM 或 AMCL 发布 map 到 odom。一个 child frame 只能有一个 parent，不能有两个节点同时发布 odom 到 base_link。

### 6. URDF 中 visual、collision、inertial 分别干什么？

**背诵答案：** visual 只决定显示；collision 供碰撞检测与物理引擎接触；inertial 提供质量、质心和惯量，决定动力学。工程上视觉网格可精细，collision 要简化，inertial 要来自 CAD/手册。缺 inertial 或碰撞网格错误会使 Gazebo 不稳定，MoveIt 也可能穿模。

### 7. 静态 TF 和动态 TF 的区别？

**背诵答案：** 固定安装关系，如 base_link 到 laser，用 static broadcaster 一次发布；随关节或里程计变化的关系用动态 TF 并带准确时间戳。robot_state_publisher 根据 URDF 和 joint_states 自动发布关节 TF，不能重复手发相同变换。

## 机械臂

### 8. 什么是 FK、IK、雅可比？

**背诵答案：** FK 根据 q 求末端位姿；IK 根据目标位姿求 q，可能多解、无解或受限；雅可比把关节速度映射到末端速度，即 xdot 等于 J(q) 乘 qdot。我的控制库实现了伪逆和 DLS，为速度控制/IK 的线性求解提供基础。

### 9. 什么是奇异位形，如何处理？

**背诵答案：** 奇异时雅可比降秩，某些末端方向无法产生或需要无限大关节速度；最小奇异值下降、条件数上升是信号。处理包括规划绕开、接近时降速、使用阻尼最小二乘、限制关节速度和选择冗余姿态。DLS 以一定任务误差换取有界 qdot，不是万能解。

### 10. 三次和五次插值有什么差异？

**背诵答案：** 三次通常满足起终点位置和速度连续；五次可再约束起终点加速度，启动/停止更平滑、jerk 更小。它们只产生时间曲线，不保证碰撞、扭矩和动力学可行，后续仍要做限幅和时间参数化。

### 11. MoveIt 2、ros2_control、Gazebo 各自职责？

**背诵答案：** MoveIt 负责运动学、碰撞检测、路径规划和时间参数化；ros2_control 抽象硬件、管理控制器；JointTrajectoryController 执行有时间信息的关节轨迹；Gazebo 是仿真硬件后端。真机时保持 MoveIt/controller 接口不变，替换 Gazebo 后端为厂商驱动或 SystemInterface。

### 12. 如何从仿真安全迁移到真机？

**背诵答案：** 先核验模型、单位、joint name、零位与 limit；先 fake hardware 再 Gazebo；真机先只读反馈，再单轴低速，再 TCP/负载/坐标系标定，最后才执行经审查的 MoveIt 轨迹。必须有实体急停、通信超时、软限位、故障状态机和日志。仿真通过只说明软件链路可能正确，不说明动力学、延迟和安全都正确。

## 移动机器人

### 13. 差速底盘运动学怎么推导？

**背诵答案：** 左右轮线速度由轮半径乘角速度得到，底盘线速度是两者平均，角速度是差值除以轮距。反解可把 cmd_vel 的 v 和 wz 转成左右轮目标速度。该模型假设纯滚动无侧滑，所以实际需要 IMU、雷达定位等修正。

### 14. 为什么 odom 会漂，如何校准？

**背诵答案：** 编码器误差、轮径/轮距误差、地面打滑和积分都会累积。直线距离主要校轮径，原地转角主要校轮距；随后用 EKF 融合 IMU，用 SLAM/AMCL 提供全局 map 到 odom 修正。不能同时让多个节点发布同一个 odom TF。

### 15. SLAM、AMCL、Nav2 的关系？

**背诵答案：** SLAM 同时建图和定位，输出地图及 map-to-odom；AMCL 在已有地图上做粒子滤波定位；Nav2 使用地图、定位、costmap 和路径规划/控制完成到点导航。开发顺序是先稳定 odom/scan/TF，再 SLAM 保存地图，再 AMCL+Nav2。

### 16. costmap 是什么，为什么会撞墙？

**背诵答案：** costmap 将静态地图、激光障碍、机器人 footprint 和膨胀层转为规划代价。撞墙通常因为 footprint 太小、laser frame/TF 错、observation source 没接到 scan 或 inflation 太小。要分别检查 global/local costmap、scan 和 cmd_vel，而不是只调速度。

## C++ 与工程性追问

### 17. 控制循环为何避免动态内存和日志？

**背诵答案：** 动态分配、锁竞争和控制台 I/O 的耗时不确定，会引入周期抖动。实时/准实时循环应预分配缓冲、使用无锁/短锁通信、节流 diagnostics，将阻塞网络 I/O 放到其他线程。当前学习节点高频 INFO 与 vector 临时分配是后续需要工程化的点。

### 18. 你的项目遇到的风险与改进？

**背诵答案：** 当前自定义速度转位置节点适合验证轨迹、限幅和 RViz 闭环，但它缺少真实反馈、抢占、超时与标准 action。我的改进路径是保留 C++ 算法库，仿真执行改用 gz_ros2_control + JointTrajectoryController，笛卡尔 jog 用 MoveIt Servo，真机用厂商驱动或 ros2_control SystemInterface，并以状态机、低速分级测试和通信故障演练作为上线门禁。

## 项目自我介绍（90 秒）

“我做的是一套从控制算法到仿真和真机部署的 ROS 2 机器人系统。底层 C++ 实现 RobotState、关节限幅、三/五次插值、轨迹缓存以及雅可比伪逆和 DLS。中间层用自定义 topic 完成速度到位置的学习闭环，并用 joint_states、robot_state_publisher 和 RViz 验证坐标和模型。执行层我迁移到 ros2_control：二维臂通过 gz_ros2_control 和 JointTrajectoryController 接入 Gazebo Sim，并由 MoveIt 2 做 OMPL 规划和碰撞检测。后续 AUBO 真机保持上层接口不变，只替换硬件后端，按只读反馈、单轴低速、TCP/负载标定、短轨迹的顺序上线。移动底盘则使用 diff_drive、EKF、SLAM Toolbox 和 Nav2，强调 TF 唯一性、轮径轮距校准和通信超时安全。”
